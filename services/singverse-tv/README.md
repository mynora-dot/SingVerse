# SingVerse Android TV

正式首页采用推荐 Banner、常驻手机点歌二维码、四个快捷点歌入口、正方形封面的横向曲库与底部演唱状态栏；支持读取 NAS 管理端「系统设置 → 电视设置」的多图轮播、标题和说明。历史评审原型仍独立保留，见 [首页视觉预览](design-preview/README.md)。

包名 `com.mynora.singverse.tv`。Kotlin / Jetpack Compose TV，授权后的业务页面采用近黑背景、中性炭灰选中标记与白色遥控焦点，顶部导航为「首页 / 点歌 / 已点 / 设置」。已接入 NAS 地址检测、管理员批准的设备授权、正式分类/歌手署名浏览、歌曲查询、本地/WebDAV 原始媒体直放、聚会队列、扫码邀请和本机主持操作。

版本沿用 AGP 8.9.2、Gradle 8.11.1、Kotlin 2.1.20、Compose BOM 2025.04.01、TV Material 1.0.0；新增 Media3 1.5.1 和 ZXing Core 3.5.3。compile/target SDK 35、minSdk 23；构建 JDK 21，字节码目标 17。

```sh
# 根目录：单元测试、编译 debug APK 并执行 lint
make tv-build
# 或在本目录使用仓库 Wrapper
./gradlew testDebugUnitTest assembleDebug lintDebug
./gradlew installDebug
```

设置 ANDROID_HOME 或本地 local.properties，安装 SDK 35 / Build Tools 35.0.0。APK 位于 `app/build/outputs/apk/debug/`，不提交生成产物。

### 模拟器遥控 UI 检查

使用 Android 平台自带的 instrumentation runner，不新增测试框架依赖。在 `services/singverse-tv/` 执行以下命令；先用 `adb devices` 核对目标 Android TV 模拟器，把示例 `emulator-5554` 换成该模拟器的 serial，保持每条 `adb` 命令都显式指定该模拟器，避免安装到物理电视。

```sh
./gradlew assembleDebug assembleDebugAndroidTest
adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell am instrument -w -r -e class com.mynora.singverse.tv.TvHomeRemoteTest com.mynora.singverse.tv.test/com.mynora.singverse.tv.TvUiTestRunner
adb -s emulator-5554 shell am instrument -w -r -e class com.mynora.singverse.tv.TvPlayerRemoteTest com.mynora.singverse.tv.test/com.mynora.singverse.tv.TvUiTestRunner
```

`TvHomeRemoteTest` 对正式 Compose 页面发送方向、确认和返回键，检查导航选中/焦点语义与颜色、四个点歌入口、输入编辑、横向曲库滚动、详情/多层弹窗焦点恢复、二维码解码和队列状态。`TvPlayerRemoteTest` 提供双模式播放器的进度预览/确认、歌词时间轴、二维码、队列、设置和音轨交互检查入口；本轮结果以验证记录为准。测试数据与 HTTP 服务仅位于 Android 测试 APK 的 fixture：使用独立随机前缀的 SharedPreferences 和设备 loopback 地址，不读取实际 NAS 凭据、不连接真实 NAS、不修改正式曲库；`TvUiTestRunner` 与 fixture 不进入生产 APK。该检查不替代微信扫码或物理遥控器验收。


## 开场

1. 启动 Java/Nginx，先在 NAS 管理页扫描自备曲库。
2. 登录入口提供手机扫码、查找 NAS、手动登录。手动输入地址前可切换 HTTP / HTTPS；输入电视和手机可达的 NAS 根地址，例如 `http://<NAS内网地址>:18080`，不使用 localhost 或容器 IP。HTTP 只允许本机/私有网络解析地址；HTTPS 使用系统证书验证。
3. 手机扫码先选定 NAS，再显示本次真实授权二维码和六位短码。微信或手机相机打开 NAS 管理页，未登录时先登录；核对设备与短码后明确批准。手动登录或发现 NAS 后则在电视填写管理员账号密码；开启 MFA 时还需认证器验证码或恢复码。两种方式均通过原有设备授权接口领取设备凭据，电视不会获得长期管理员权限。凭据通过 Android Keystore 加密保存，应用不允许备份。
4. 从首页快捷入口或「点歌」中心进入歌曲搜索、歌手、分类、歌单，加入待唱后在底部状态栏/已点确认开始。本场手机点歌二维码常驻首页，其他业务页通过顶部「手机点歌」打开相同邀请面板；亲友填写昵称后加入。主持授权或撤销参与设备在 TV 设置页完成。

方向键导航、确认键操作；返回键先关闭弹层/控制层及详情，搜索、歌手、分类和歌单页返回点歌中心，再返回首页。页面、详情和弹窗关闭时按页面记忆恢复原焦点，横向曲库随焦点滚动。演唱页确认键打开控制，支持暂停、继续、重唱、±10 秒与本机停止。本机点击切歌直接开始下一首，不再重复确认；在线、前台自然播完且服务端确认结束后，自动播放待唱队列下一首，已唱歌曲保留完成状态，队列为空则停留在演唱结束。暂停、停止、播放失败、远程或结果未知的交接不触发自动续播。应用后台暂停，进程重建须重新确认开唱。

## 边界

播放沿用 Media3、Java 授权协商以及既有直放/HLS兼容路径，TV 不修改媒体原件。文件不能解码时显示真实失败，可重试/重唱/换歌；原唱/伴奏角色未知或不可切换时显示不可用，不猜测轨道含义。无评分、录音或消人声。正式分类复用 NAS 已应用结果，歌手按精确署名分组；支持有效歌名、歌手、专辑的拼音全拼/首字母和已解析歌曲编号精确检索；多音字采用词典首读音，不自动归并歌手或作品。服务端共享只读索引在 30 秒内刷新，首页刷新使索引失效；超大曲库仍需按实际规模验收。

设备与参与者使用独立 Bearer 身份，不能访问管理接口；WebDAV 凭据保留在 Java。主服务持久化业务状态，电视只执行命令与上报真实播放。断线可本地暂停/停止，重新同步不自动重发点歌。

完整设计与转码后续安排见 [TV 端开发设计](../../docs/tv-development-design.md)。构建、模拟器和 HTTP 测试不代表微信、真实电视/音响、NAS 或 API 21 兼容性验收。

## TV 视觉与页面组织

`TvComponents.kt` 统一颜色、形状、间距、按钮、状态标记、封面卡片、焦点记忆、空态与确认后编辑输入；`TvScreens.kt` 组织页面和弹窗，`TvHomeScreen.kt` 组织首页。视觉采用 Apple TV 式内容优先原则：背景 #050505、面板 #1C1C1E、主文字 #F5F5F7、次文字 #A1A1A6，主操作使用白底黑字。页面选中以中性底色和文字明度表达，遥控焦点使用白色细边、柔和层次和约 180ms/1.04 倍缩放；不再使用金色主题或蓝色光晕。使用系统中文字体和显式行高，不依赖实时模糊、新系统特效或额外字体依赖。

顶部只保留「首页 / 点歌 / 已点 / 设置」，已点显示待唱、交接待确认和当前演唱歌曲的合计数量。点歌中心以搜索为主入口，保留歌手、分类和 NAS 共享歌单全部业务入口；首页快捷入口使用轻量中性表面，接近全宽的推荐 Banner、真实封面与歌词承担主要视觉。歌曲封面统一 1:1、圆角及 Crop，不拉伸；首页曲库横向滚动，列表与网格为焦点描边留白。无封面使用统一渐变和绘制音乐图标，不插入示例歌曲或图片。

顶部导航随实际遥控焦点立即切换页面，无需确认；切换后焦点留在导航，左右继续浏览，下键进入内容。分类页的语种、年代、风格、情绪、场景和自定义标签也随焦点直接更新卡片，并将新维度滚回顶部。当前标签重复确认不重复加载；关闭弹窗、详情返回和恢复页面焦点不会触发额外切页。歌曲入队、播放及分类卡片进入歌曲仍由确认键执行。

首页 Banner 展示真实曲库歌曲，可打开点唱详情或直接加入已点；轮播读取 NAS 配置与真实歌曲列表，遥控器停留 Banner 时暂停自动切换，手动切换重新计时。手机邀请以辅助卡片融入 Banner，使用原有会话邀请接口与 ZXing，按实际显示像素生成 M 级纠错二维码，避免固定图片缩放破坏码点；不更改 `/party/#invite=` 连接协议。邀请失效后自动更新，换 NAS/会话丢弃旧结果；网络和邀请失败显示真实状态，确认可重试。设备数来自本场未撤销的参与者，表示有效加入数，不能推断手机当前在线数量。

底部状态栏常驻业务页，显示正方形封面、歌名、歌手、真实演唱/等待状态、已点数量，以及返回演唱、确认开唱或新聚会入口。待唱列表只展示 WAITING 项，每行显示真实方形封面、顺序、歌名和歌手，不展示点歌人/设备名称；缺图复用统一占位。已点通过整行焦点进入行内操作，播放器内采用宽版队列弹窗。设置采用分组与详情区域；播放设置用有界滚动内容和数值步进器呈现音量、音调与同步。简单提示使用紧凑弹窗，邀请、队列和播放设置使用较宽面板。全屏演唱保留原有播放器及双模式控制层。输入框按确认键进入系统键盘，完成/取消恢复原行焦点；仅最上层弹窗可以接收焦点，返回逐层关闭并恢复来源位置。列表目标被回收时，先滚动使其可见再恢复焦点。

当前 NAS 授权、队列、播放器生命周期与 API 保持原有协议。本轮检查记录见 [工程验证记录](../../docs/verification.md)；构建、模拟器截图与二维码解码不能替代真实电视遥控器、微信扫码、NAS 网络和音响验收。

首页推荐区的「播放」与点歌中心四个入口均采用中性深色底，实际遥控焦点通过白色描边与缩放表达；「搜索歌曲」不常驻白底。曲库横排任意歌曲按上键直达「查看全部」，再按下键返回原歌曲；仍保留原有快捷点歌与横向滚动路径。首页卡片按可用高度和字体缩放预留完整歌名、歌手及焦点留白，空间不足时缩小封面，避免歌手文字被截掉。

## 列表点歌

搜索结果、分类筛选结果、歌手歌曲和歌单歌曲统一为表格式列表，固定表头显示序号、歌曲、歌手、版本、时长和点歌状态；小封面、长文本省略和未知时长占位均使用真实曲库信息。歌手与歌单顶部使用紧凑信息栏，首页横向曲库及各类入口卡片保留原交互。

分类卡片按确认直接进入该分类的歌曲列表，聚焦第一首，无需再点「查看歌曲」。每次按当前单个分类重新查找，清除旧关键词、其他分类与页码；「未分类」也直接进入结果。返回键先从详情回到歌曲，再回到原分类卡片，保留分类维度与滚动位置。

分类页使用四列紧凑卡片与单行标题说明，1080p 默认及 1.15 倍字号下可完整浏览两排。卡片以名称、歌曲数量和同行「已选」标记为主，最小高度 88dp、随字体扩展，长名称省略；保留封面、缺图占位与白色焦点描边。

上下键选择歌曲，确认直接加入队列，右键查看完整歌曲详情；详情返回恢复来源行和滚动位置。点歌成功显示约 2.5 秒提示、更新行内已点数量与底栏数量，保持当前行，不自动开唱。请求中连续确认只提交一次，完成后再次确认可有意重复点同一首。失败沿用操作提示，结果未知时只能核对后使用原 requestId 重试；重试成功关闭提示并恢复来源焦点。换 NAS 或聚会丢弃旧请求的界面反馈。

歌曲列表保留每页 20 首和服务端原顺序，新搜索/筛选重置到顶部，翻页完成后聚焦新页第一行；列表为焦点描边留白，行高随字体扩展。`TvHomeRemoteTest` 覆盖四条真实入口直接点歌、详情返回、滚动分页、请求中防重复、离线/拒绝/未知结果重试及连接切换回归，实际执行结果见工程验证记录。

## 实际后端数据绑定

连接授权后首页调用 `/api/v1/tv/home`，曲库横向列表与全库数量独立于找歌结果；进入首页和点击“刷新曲库”重新读取，停留首页时约每 30 秒同步一次。找歌与歌手分别持有搜索词、页码和总数，切页不互相覆盖。分类进入时刷新正式词表，停留时约每 30 秒同步；队列及本场参与者仍走已有聚会快照接口。

首页歌曲卡片或歌曲列表右键查看详情时，通过 `/api/v1/tv/library/songs/{id}` 获取当前详情，显示真实可用的专辑、发行日期和时长；列表直接点歌无需先请求详情。更新元数据或封面后依展示 revision 重新加载封面；歌曲已移除时提示真实 404。换 NAS 清除旧列表与筛选，迟到详情响应不能重新打开已离开的页面。接口必须由新版 Java 提供；开发联调地址不会硬编码进产品，电视仍输入自己 NAS 的地址并经管理员授权。

本地联调可访问宿主机 `http://127.0.0.1:18080`；Android 模拟器连接同一服务填写 `http://10.0.2.2:18080`。这只是模拟器访问宿主机的测试地址，真实电视与手机应改用手机可达的 NAS 内网地址。

## 音轨、歌词与声音

演唱控制或「设置 → 播放设置」提供音轨、歌词字幕、声音输出与同步面板。音轨仅列 Media3 判断设备可支持的轨道；双声道 PCM 可选择左、右、混合单声道。原唱/伴奏通过用户听辨后记录当前轨道与声道，按 NAS 曲目及媒体/元数据 revision 保存到本机；源文件变化后旧映射失效，不猜测第二轨的含义。

Java 提供同目录、同文件名主体的 `.lrc` / `.srt` / `.vtt`（小写扩展名），单文件上限 128 KiB；支持严格 UTF-8、带 BOM 的 UTF-16。缺少有效外置 LRC 时，也读取已经保存的 WebDAV/共享缓存或本地扫描内嵌歌词，不在播放时重新提取媒体。旧版本本地扫描未保存歌词的歌曲需要重新扫描一次。仅从已配置本地/WebDAV 来源读取，拒绝越界路径/重定向，源凭据不传电视。TV 解析普通/增强 LRC、SRT、VTT，按真实时间戳显示；增强 LRC 按已有词时间戳高亮；逐词时间损坏或不能覆盖完整正文时，回退完整行显示，避免丢字。无时间歌词预览实际前两行文本并标记「未同步歌词」，不提供全文浏览或编造同步时间。加载、读取失败、首句前等待、间奏和无歌词分别展示。内嵌字幕交给 Media3，可选择识别出的字幕轨或关闭。文本可读不代表编码字幕可解码。

升降调范围 ±6 半音、速度保持 1 倍；应用音量 0–100%。输出设备是 Android 优先路由请求，实际 HDMI/蓝牙/音响路由由系统协商。外置歌词偏移 ±5 秒；PCM 音频可延后 0–500ms，默认 0；内嵌字幕沿用原时间轴。音量和偏移保存在本机，音调每首恢复原调。音频处理发生在电视 PCM 播放链，不生成媒体副本，也不改变 NAS 文件。真实音画同步与音响效果必须真机听辨。

断线后仍可本机暂停/停止；有未确认请求时阻止新点歌，用户可用原 requestId 重试或放弃本次重试。重连先读取快照，明确的 4xx 拒绝会解除请求占用；不会自动重发点歌或跳歌。播放进度每 200ms 取播放器实际位置，上报约每 5 秒。


## 双模式演唱播放器

`TvPlayerScreen.kt` 按当前完整媒体探测结果切换视频/音频布局；探测尚未返回时才参考 Media3 实际识别到的轨道类型。附带封面的视频流不作为 MV；`audioRoles.streams` 只描述音频轨道，不能用它推断媒体没有视频。只有确认纯音频后才使用音频布局，未知类型保持视频容器，避免误把 MV 归入音频模式。

视频模式继续使用原有全屏 `PlayerView` 与默认缩放策略，不改视频显示区域、宽高比或视频画面内自带歌词的位置。Media3 内嵌字幕继续交给 `PlayerView`；外置 LRC/SRT/VTT 沿用已解析时间轴和同步偏移。右侧共享下一首与动态手机二维码，更多设置可隐藏辅助卡片，方便观看原画面。下一首取真实聚会队列的交接待确认项或等待项。在电视点击「切歌」不再弹出确认；NEXT 成功、STOP 已处理且仍是该交接项时，使用最新 revision 发送 START 并开始下一首。空队列只停止，远程/恢复/结果未知的交接仍需明确确认开唱。

音频模式独立展示正方形封面框，图片用 `ContentScale.Fit` 保留原比例，不拉伸或裁掉封面；缺图使用统一绘制占位。歌名、歌手取当前歌曲的 `title`/`artists`，专辑取 `album`，年份取有效 `releaseDate`，风格通过正式分类 `GENRE` 标签解析，时长取真实歌曲时长或播放器时长。缺失信息隐藏，不补造示例值。音频格式、码率、采样率和声道数依据当前实际解码音轨；尚未返回的参数隐藏，技术详情放在“音质详情”，不由封面、扩展名或码率推断 HQ/无损等级。

音频歌词位于元数据下方，复用现有歌词解析器、原媒体播放时间轴和歌词偏移，显示当前行及下一行；没有可用歌词时显示简洁状态。内嵌文本歌词沿用实际解码结果；没有下一行时间戳时不编造预告。歌词下方中性色动效仅表示播放状态，播放时轻量变化、暂停后静止，不是真实频谱分析。

两个模式共用 `TvPlayerControls.kt` 的进度和核心按钮、原唱/伴奏分段选择、下一首卡片、手机二维码、队列及设置对话框。原唱/伴奏优先在当前 Media3 资源内切换已识别音轨/左右声道，不重新申请资源、重置进度或改变暂停状态；重复选择当前角色不触发切轨。生成伴奏首次仍需要协商并加载，之后在同一播放器合并的原唱与伴奏音轨间切换。当前资源没有目标轨时才重新协商，切换完成时使用实际播放位置继续。白色填充表达实际选中角色，白色细边和缩放表达遥控焦点；不可用角色保留明确提示。播放设置由 `TvPlaybackSettings.kt` 按音轨、歌词字幕、声音输出、同步四类分别显示，保留角色订正、声道、输出路由、音量、音调和同步能力，音频模式不展示视频画质项。

聚焦进度条后，左右键每次只预览 ±10 秒，按确认才实际跳转；返回或移走焦点取消预览，上下方向继续使用原生焦点导航。视频控制栏在播放中无操作约 8 秒后自动收起，确认或上下键可再次打开；返回先关闭顶层弹窗，再收起视频控制栏，最后返回首页。音频模式保留控制栏。已点和设置通过独立对话框打开，关闭后恢复来源焦点。

收藏是这台电视上的个人书签，按 NAS 地址分别保存，最多 200 首，不上传服务端或与手机同步。更多设置中的“本机收藏”可浏览并逐首加入已点；收藏和 NAS 共享歌单独立。

双模式布局、遥控、字幕及播放回归需要本轮实际执行检查；模拟器不能替代真实电视、音响、微信与 NAS 验收。

## 局域网发现

连接页点击「查找局域网 NAS」，通过 Android NSD 发现 `_singverse._tcp.`，15 秒结束，点击候选预填地址并进入账号密码页，仍需服务身份检查与管理员身份验证。列表只表示 mDNS 已发现，不虚构在线探测或延迟。Java 原生部署可配置 `SINGVERSE_TV_DISCOVERY_ADDRESS=<本机内网IP>`、`SINGVERSE_TV_DISCOVERY_PORT=<实际HTTP入口端口>`；默认关闭，不自动暴露服务。当前广告指向 HTTP 内网入口；HTTPS 入口手动填写。

桥接 Docker 的组播和容器地址通常不能供电视使用，请在 NAS 宿主机发布同一服务类型，例如 Avahi 的 `_singverse._tcp` 服务配置（端口为实际 Nginx 入口）；macOS 可用 `dns-sd -R "SingVerse NAS" _singverse._tcp local. <端口>`。仅在入口已绑定可达 LAN 地址后发布。模拟器宿主机隔离网和访客 Wi-Fi 不保证组播互通，手填地址始终可用。

## 签名与应用内更新

`make tv-release` 要求环境提供 `SINGVERSE_TV_KEYSTORE`、`SINGVERSE_TV_STORE_PASSWORD`、`SINGVERSE_TV_KEY_ALIAS`、`SINGVERSE_TV_KEY_PASSWORD`；密钥由发行方保管，不入库。版本用 `ORG_GRADLE_PROJECT_singverseVersionCode` / `ORG_GRADLE_PROJECT_singverseVersionName` 或 Wrapper 的对应 `-P` 参数递增。任务生成 `app/build/tv-release/singverse-tv.apk` 与 `release.json`，执行 release lint。未配置密钥时明确失败；普通 debug 构建不需要正式密钥。

将两个文件一起复制到 NAS 的专用发布目录，设置 Java 的 `SINGVERSE_TV_RELEASE_DIRECTORY`。Docker 中目录必须是容器内路径，例如持久卷 `/data/tv-releases`，宿主机可用 `docker compose -f compose.app.yaml cp <文件> singverse-java-backend:/data/tv-releases/`，自行创建目录后再发布；不要放到媒体原件目录。发布期间不应覆盖正在下载的文件，建议停用发布目录配置后成对替换再启用。

「设置 → 应用更新」检查实际 manifest，下载后核对大小、SHA-256、包名、递增 versionCode 及与当前应用完全一致的签名，再经 Android 安装确认。Android 8+ 首次需要在系统页面允许此应用安装并返回重试；不静默安装。调试签名与正式签名不同，不能将正式包作为 debug 包的应用内升级；首次正式安装由发行方安排。`release.json` 只声明 versionCode/versionName，服务端实际计算包大小和 SHA-256，单包最多 256 MiB。未发布时显示真实空态。

快照另含 stateRevision（包含播放事件的持久版本），TV 不接受同会话较低版本、换会话或换NAS后的迟到状态；队列命令仍提交 revision。

封面请求限制响应2MB，解码最长边约512px，16MiB有界内存缓存按NAS/封面路径/revision分开；换NAS清空缓存，减少翻页和返回时的重复读取。


### 分类封面卡片

分类改为三列16:9图片卡片，封面从Java的正式标签投影coverPath/coverVersion读取，设备Bearer鉴权，按内容版本更新有界缓存。聚焦使用白色描边、柔和层次与轻微放大，已选使用独立白色标记；卡片保留真实歌曲数量、长名称截断和加载失败提示。未上传时显示低饱和渐变与分类名称，不填示例图片。管理端「歌曲分类 → 分类词表」上传/更换/移除后，重新进入TV分类即可刷新，停留时约30秒同步。分类逻辑仍同维OR/跨维AND。

分类封面大卡片保留最长边1280px解码以适配4K，歌曲缩略图仍为约512px，两者共用16MiB有界缓存；替换图片时取消旧请求不会覆盖新版本。

## 自动歌手库

扫描后按歌曲有效署名自动生成，不再人工建档/关联。管理端歌手详情可打开歌曲编辑器订正歌手，NAS 覆盖值优先于文件标签并在重新扫描后保留；恢复扫描值需确认。首次后台从网易云/QQ 核对歌曲并取真实歌手头像，失败有限重试，无可靠匹配保留占位。上传图片优先，移除后暂停自动补图。TV 自动展示同步结果和受权图片，保留返回焦点。迁移 `202610290008`，新增接口、来源与状态见 OpenAPI 和 [自动歌手库说明](../../docs/artist-library.md)。

歌手详情横幅优先显示独立背景图；只有头像时，TV 在内存中生成低分辨率柔化背景并压暗，不回写 NAS；没有任何图片时保留渐变。生成背景带文字标识，头像和返回按钮的布局及焦点不变。

## 歌单分类

「点歌 → 我的歌单」展示 NAS 管理端保存的共享歌单，支持搜索、分页、真实歌曲封面/缺图占位、详情和按保存顺序浏览歌曲，并沿用歌曲详情点歌流程。歌单浏览与聚会队列独立，不自动入队整张歌单，不重建播放器；返回恢复歌单卡片焦点。管理端编辑内容随曲库轮询同步，已删除歌单返回列表。空歌单/已移除歌曲如实展示，详见根 `docs/playlists.md`。

## 兼容播放

TV 已接入能力协商、Media3 HLS、画质切换和失败兼容重试。播放位置/歌词使用原媒体时间轴；新的原唱/伴奏标记使用源流 ID。当前软件解码/滤镜加硬件编码的服务端边界和真机待验收项见[转码说明](../../docs/transcoding.md)。

Java 命中整曲缓存时，即使请求非零起点也可返回 HLS `offset=0`。TV 对所有播放方式均按 `max(0, 请求原时间轴位置 - offset)` 设置播放器起点，回报继续加回 offset；复用整曲缓存或切换设置时保留播放位置。

### 全曲库原唱/伴奏

演唱设置中的音轨标记现在写入 Java 全曲库元数据，使用源 stream ID 和修订号；订正不改变当前播放，点击主控制栏“原唱 / 伴奏”时按现有机制切换。单音轨生成的伴奏与原视频通过同一个 Media3 播放器合并，按 HLS 原时间轴偏移对齐，支持继续拖动。单音轨仍可返回原唱；失败或取消的分离任务不会显示为可用伴奏。大屏按钮沿用遥控焦点组件，遥控真机、HDMI/蓝牙音画同步仍须验收。

单轨左右声道的既有标记继续保存在本机并按素材版本隔离；全曲库纠正仅保存两条源音轨角色，立体声不会被自动当作双音轨。

## 登录页面与最近设备

`TvLoginScreen.kt` 为连接模块提供独立的入口、账号表单、局域网发现、手机授权和最近登录页面。采用近黑背景、白色焦点、约 1.04 倍焦点缩放和独立 HTTP / HTTPS 分段控件。布局以 960×540 逻辑画布等比适配 16:9 大屏，保留安全边距；输入按确认键打开系统键盘，完成或取消后恢复原行焦点。密码默认隐藏，可独立切换显示。

成功连接后在电视本机记录最多 10 个 NAS 的地址、名称、账号和上次登录时间；相同规范地址更新到最前。记录不包含密码、MFA 码或管理员会话，选择记录仍进入账号验证。当前设备 Bearer 凭据的自动恢复保持原有行为，切换 NAS 清除该活动凭据。临时管理员 Cookie 只存在于本次登录的隔离内存会话，CSRF 在每个管理写请求前重新获取，授权后注销。

退出页面、更换 NAS 或刷新二维码会取消旧轮询，迟到结果不能覆盖当前流程。二维码只包含本次公开批准信息，不包含 pollSecret 或设备 Bearer；手机须能访问同一 NAS 地址。扫码页需要同步发布本仓库前端的电视设备页以预填本次申请和授权码；未更新前端时仍可手动填写电视显示的六位码。服务端接口、数据库及权限规则未改动。

## 首页个性化与多图轮播

管理端「系统设置 → 电视设置」（`#/system/tv-settings`）配置所有已授权电视共用的首页。支持最多8张JPEG/PNG封面（每张2MB以内、4096像素以内），名称、启停、上下排序、首页标题/说明、自动轮播开关与5–60秒间隔。图片沿用受限上传校验，归一为最长边1280px的JPEG，和配置一起保存在业务数据库；数据库备份包含这些图片，无需额外挂载图片目录。不接受远程图片URL。

上传即保存并启用；文案/启停/排序需要点击保存。上传和移除前需先保存草稿，避免丢失未保存修改。所有写入校验全局revision，冲突须重新加载；移除需明确确认。配置仅管理员Cookie会话及CSRF可写，设备Bearer不能修改。TV仅能读取已启用的图片，亲友身份不能读取首页配置图片。

`/api/v1/tv/home`兼容增加`appearance`与`featuredPlaylists`，后者只展示真实共享歌单，不伪造热度、播放历史或示例歌曲。首页约30秒同步，刷新曲库/重新进入首页也会读取；更换NAS清空旧配置。旧后端缺少新字段时使用默认文案与曲库背景，不影响登录。未上传或全部停用时，主视觉优先展示真实歌曲封面，缺图使用统一绘制占位。生产首页不会读取Debug演示背景。

首页以960×540逻辑画布随屏幕缩放，适配1080p/720p；顶部四导航，点歌能力归入点歌中心。首页常驻动态邀请二维码与正方形封面曲库，底部保留本场演唱/下一首和开始新聚会，刷新曲库位于点歌中心。页面选中为中性炭灰，遥控焦点为白色细边及约1.04倍缩放；页面、详情返回和弹窗关闭恢复来源焦点。轮播同步显示当前推荐歌曲与背景，不移动遥控焦点；Banner内聚焦时暂停自动切换，手动切换重新计时，退出首页、离线或退到后台时不自动轮播。图片加载复用16MiB有界缓存，响应最多2MB，按NAS、路径和版本区分，换NAS的迟到图片不能写回新连接。

部署需同步更新NAS后端/完整管理前端和TV APK。后端启动自动应用SQLite/MySQL迁移`202611050001`；当前已完成SQLite集成验证，MySQL迁移需目标环境验收。物理电视、4K及客厅观看距离仍需实机确认。

## 待唱队列

「已点」页只列 WAITING 歌曲，按服务端顺序显示序号、正方形封面、歌名和歌手，不展示点歌人或设备名称；已唱、跳过、撤回和失败记录不展示。正在演唱或等待电视确认的歌曲独立置顶，不计入待唱数。当前没有播放交接时才显示「开始下一首」，未确认的交接使用「确认开唱」，已确认交接显示准备状态和「返回演唱」。

遥控聚焦歌曲行显示可用的置顶、上移、下移、移除操作，确认键进入行内操作，首尾隐藏无效移动方向。没有待唱时显示空态和「去点歌」，隐藏清空按钮。该页不显示重复的底部演唱状态栏；暂停/恢复接单、结束聚会与开始新聚会位于「设置 → 聚会管理」。

歌曲详情采用左侧正方形封面、右侧歌名与资料、横排点唱操作；默认焦点为白底黑字「加入待唱」，白色细边表示遥控焦点。缺失的专辑、日期、时长和来源不显示，未知版本显示「版本待确认」。详情期间顶部归属「点歌」，返回后保留原页面及歌曲焦点，底部继续显示演唱状态。

搜索歌曲页使用同排标题与说明，封面按结果区可用高度缩放，保留正方形比例及一整行歌名、歌手和遥控焦点空间；更多结果继续用方向键向下浏览。

弹窗显式沿用主页面的 TV 逻辑画布密度，避免独立 Android Dialog 窗口恢复系统密度后导致标题、设置项及说明在大屏上缩小；播放器的更多设置、播放设置、音质、收藏和队列弹窗共用此规则。
