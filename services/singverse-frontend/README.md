# SingVerse 网页前端

工程名 `singverse-frontend`，统一维护亲友点歌网页与NAS管理网页。Vue 3 + TypeScript + Vue Router 4 + Vite + Element Plus，采用多页面入口；目前亲友侧只有原生HTML/CSS欢迎页，管理侧包含概览、系统状态、真实健康检查及失败重试。

## 目录与入口

```text
singverse-frontend/
  party/index.html            亲友入口 /party/，当前欢迎页
  public/party/assets/welcome.css   亲友欢迎页样式，构建时原样复制
  admin/index.html            管理入口 /admin/
  src/admin/
    main.ts                   管理端启动
    App.vue                   语言 Provider 与布局入口
    app/                      路由注册/守卫、布局、全局样式和 404
    core/auth/                跨业务共享的认证请求、账号状态和会话查询
    core/hosting/             根路径与 /admin/ 的入口挂载路径工具
    modules/
      auth/                   登录与 MFA 验证页面、路由
      overview/               概览页面、路由
      system-status/          健康 API、健康卡片、状态页和路由
      system-parameters/      改密与 MFA 设置页面、路由
      media-library/          媒体库 API、类型、页面和路由
      filename-parser/        共享规则维护、方案组合/预览、类型、API 和路由
    shared/http/              通用同源只读 HTTP 客户端和错误类型
  tests/                      前端行为测试
  vite.config.ts              同一工程的两入口构建
  dist/                       两入口共享的完整静态产物，不提交
```

亲友入口 `/party/` 与管理入口 `/admin/` 共用一个工程、依赖锁文件及构建命令。管理页面使用 `/admin/#/overview` 和 `/admin/#/system`；管理页有登录守卫，后端独立强制授权；新增系统管理→系统参数（改密与MFA）。当前没有配对、点歌、队列、设备或播放业务，不使用模拟数据冒充真实状态。

## 开发与检查

需要Node.js 22.19+（22 LTS，或工具支持的24/26系列）与npm。依赖以package-lock.json为准，不需要全局安装Vite。

```sh
# 仓库根目录
make frontend-setup
make frontend-dev
# 另开终端构建前端、启动Java
make frontend-build
cd services/singverse-java-backend
./mvnw spring-boot:run
```

开发亲友入口 `http://127.0.0.1:5173/party/`，管理入口 `http://127.0.0.1:5173/admin/`，均由Vite本地提供。`/api`默认代理至 `http://127.0.0.1:8080`。使用其他开发后端时执行 `SINGVERSE_DEV_BACKEND=http://127.0.0.1:8081 make frontend-dev`；该配置仅用于开发代理，不写入浏览器产物。

```sh
make frontend-check   # Vitest、vue-tsc、两个入口的生产构建
make frontend-build   # 类型检查及生产构建
make web-check        # 构建后实际HTTP验证亲友和管理两个入口、JS/CSS
make java-backend-test # 构建前端、Maven verify并打包JAR
```

`npm run preview`可在 `/admin/` 和 `/party/` 预览完整静态产物，不代理后端；健康联调使用开发代理或Java真实托管。开发和预览只监听回环地址。直接用file协议打开源码HTML不能运行Vite模块。

## 静态交付与未来Go

一次构建产出完整的dist：party/index为亲友页面，admin/index为管理页面，构建JS/CSS在assets，亲友样式在party/assets/welcome.css。Java Maven将整个dist复制到target/classes/static并打入JAR，不向Java源码目录生成文件；缺少任一入口时明确失败。直接执行Maven前也需make frontend-build，Maven不会自动更新已有产物。

生产不需要Node进程或CDN；Docker交付使用Nginx前端容器，执行根目录 `make docker-up` 即可联合构建并启动Java，访问 http://localhost:18080/ ，详见[Docker说明](../../docs/docker.md)。未来Go继续在根路径托管同一完整dist，并保持同源API、HTTP状态和授权语义，无需重写Vue工程。当前调用 `/api/health` 和 `/api/v1` 账号/MFA接口，API适配层强制请求带 `/api` 前缀；账号契约已建立，后续业务按[API约定](../../contracts/openapi/README.md)扩展OpenAPI。浏览器不直连数据库或Python内部服务。

详见[托管契约](../../contracts/frontend-hosting.md)。当前验证根路径部署，额外反向代理前缀需要同时调整资源、路由、API和服务挂载。网页检查不代表Android/iOS微信扫码、NAS部署或Go实际运行已验收。

## Nginx根路径管理

Nginx对外根路径直接提供管理页面，点歌页使用 `/party/`。构建资源通过 `/assets/` 独立提供，管理hash路由按实际访问地址确定基址，因此同一份产物可在根路径或 `/admin/` 打开。Nginx配置及Docker复制路径见[后端Nginx说明](../singverse-java-backend/nginx/README.md)。未来业务请求统一使用 `/api/v1`，代理保留 `/api` 前缀。

## 媒体库管理

管理侧 `#/library/media` 通过“歌曲库 → 歌曲位置”进入。以卡片展示少量本地目录和 WebDAV，不再显示筛选栏与分页表格；超过 100 个来源可继续加载。统一添加入口选择来源类型，本地目录通过服务端文件夹选择器选择，WebDAV 填写地址与可选凭据。名称留空时自动生成；定时扫描和解析方案位于“更多设置”。扫描完成留在当前页，可点击“查看歌曲”进入对应来源。本地结果保留到离开页面，WebDAV 后台任务可恢复。详见[媒体库说明](../../docs/media-library.md)。

## 模块边界

采用按业务聚合的目录，每个 `modules/<业务>/` 自己维护 `routes.ts`；需要时在内部增加 `api/`、`views/`、`components/` 和 `types.ts`，不预建空目录。`app/router/index.ts` 负责组合路由、登录守卫和页面标题；`app/layouts/AdminLayout.vue` 负责导航及管理外壳。现有 hash 路径、菜单和双入口构建保持不变。

页面调用本模块 API 适配器；跨模块账号状态和带 CSRF 的业务请求由 `core/auth` 提供。`shared` 只放通用能力，不引用业务模块或应用入口。模块不反向依赖 `app` 中的布局和路由实例；入口挂载路径工具归 `core/hosting/`，供路由和系统状态页复用。概览复用系统状态模块的健康卡片，避免复制健康请求与展示逻辑。测试引用实际所属模块，移动源码时同步更新 mock 路径。

当前没有为分包增加状态管理依赖、独立 npm 工作区或新的构建入口；新增页面沿用模块结构即可。

## 解析规则与解析方案

“曲库 → 解析方案”（`#/library/filename-parser-profiles`）是日常使用的唯一主路径，页面按“填文件名 → 挑格式 → 保存”四步组织：第 1 步输入媒体文件名并点“找出能识别的格式”，一次 `POST /profiles/preview` 携带全部内置格式候选，按返回的逐条 `attempts` 判定哪种命名格式能识别；第 2 步把内置格式渲染成卡片墙（`button.format-choice`），标出能用、只认出一半、识别不了、已在方案里，点一下即追加为成员、再点移出，不再使用铺满页面的系统下拉；第 3 步是方案名称与保存；第 4 步“我要自己排顺序、启停，或用自定义格式”折进 `<details class="profiles-advanced">`，保留原有序成员列表、启停、`添加已有规则`（此处选项已收窄为非内置定义）、`解析当前方案` 与完整预览面板。主区不出现“规则”一词，用户可见名词统一为“格式”。检测只在点击时发起，不自动触发；改文件名只把旧检测结果标记为过期。方案保存无需示例命中；切换/离开/刷新保护未保存草稿，成员或输入变化标记旧预览，迟到响应丢弃，冲突时“加载最新配置，保留草稿”并标明失效引用。

“曲库 → 解析规则”（`#/library/filename-parser`）降级为高级页，只维护单条自定义定义和引用情况，新增/编辑直接编译校验保存；内置定义只读、可复制，改由方案页的格式卡片提供，页面顶部明确提示平时不需要来这一页并给出返回主路径的链接。方案复制不复制定义；共享规则修改影响所有引用方案。默认方案可改名和清空、不能删除，引用中的规则不能删除并列出方案链接。旧路由和三个旧 API 保留兼容，新数据按 schemaVersion=2 保存，媒体来源可绑定完整方案，本地扫描会使用已保存的启用成员顺序提取并保存歌曲数据。详见[规则与方案说明](../../docs/filename-rules.md)。

## 管理页面布局与视觉主题

`src/admin/app/styles.css` 是唯一的全局样式入口，按“token → 基础 → Element Plus 主题 → 外壳 → 页面通用 → 业务模块 → 响应式”分段。颜色、圆角、间距、阴影、字号都取自 `--sv-*` 变量，不在组件里写死十六进制值；Element Plus 通过覆盖 `--el-*` 变量跟随同一套色板。管理端与亲友欢迎页共用中性石墨 + 低饱和靛蓝的深色品牌带（`--sv-deep-*` 深色面、`--sv-brand-*` 主色、`--sv-accent-*` 深底高亮），绿/琥珀/红仅作为成功、警告、危险的状态色；欢迎页样式在 `public/party/assets/welcome.css` 内自带同名变量。

深色侧栏 + 浅色工作区：侧栏承载品牌与分组导航（概览、曲库、系统），顶栏只放面包屑、亲友入口与账号菜单，页面正文统一 `--sv-content-max` 宽度。页面头保持单行：`h1` 与 `.page-description` 同行排布、操作按钮靠右，不再放英文小标（eyebrow）与独立描述行，避免与顶栏面包屑重复占高；默认密码提示目前已从管理页移除；后续待实现为弹窗提醒。概览以“状态优先”组织：深色舞台带、服务连接与快速访问两列、后续功能列表。媒体库、解析规则、解析方案与系统参数使用统一的面板头、表格与标签层级；所有原生 `select`（媒体库与歌曲筛选栏、添加来源弹窗的解析方案、规则弹窗的「添加已有规则」、刮削批次的状态与排序）由 `styles.css` 的全局 `select` 规则统一外观：32px 高与 `ElInput` 同轴、`--sv-r-sm` 圆角、`appearance: none` 后用两层渐变自绘箭头，箭头颜色由 `--chev` 驱动随 hover/focus-visible/disabled 变化；Element Plus 不渲染原生 `select`，因此组件内部不会被这条规则命中。`textarea` 等其它原生控件仍走 `.native-field`。解析方案页是“左导轨 + 右步骤流”两列（`252px minmax(0,1fr)`）：左侧粘性方案列表条目显示格式数与“默认”标记，右侧按 1～4 编号排成检测卡、格式卡片墙、方案与保存、高级折叠区，不再把试解析面板拉成第三列。格式墙用 `repeat(auto-fill, minmax(216px, 1fr))`，`≤760px` 收成单列并把步骤头也压成窄列；`≥1600px` 只放宽 `--sv-content-max`。卡片标记、示例文件名与“识别为：歌手 … · 歌名 …”结果行都在同一张卡内，状态用 `.usable`/`.dim`/`.applied` 修饰。窄屏时侧栏变为可滑出的抽屉，顶栏开关收成图标（连同“亲友入口”文字与面包屑前缀一起隐藏，保证 390 px 不换行溢出），切换页面后自动收起；列表保留横向滚动以完整展示字段与操作。

动效只有波形均衡器、健康状态脉冲与抽屉位移，全部在 `prefers-reduced-motion: reduce` 下关闭。

媒体库列表提供“扫描”和“歌曲”操作；WebDAV 在后台执行并轮询状态，刷新页面可恢复，完成后提供“查看歌曲”入口；本地扫描完成后在卡片显示歌曲与复核数量，用户可主动进入对应来源的歌曲列表。两类来源的表单都必须选择有效方案，加载失败时阻止保存并提供重试。扫描请求允许 60 秒超时，常规请求仍为 10 秒；后端单次扫描上限和原件保护规则见[媒体库管理](../../docs/media-library.md)。

## 歌曲管理

“曲库 → 歌曲管理”（`#/library/songs`）由 `modules/song-management/` 维护，集中展示本地目录及 WebDAV 扫描保存的歌曲，调用同源 `GET /api/v1/media-songs`。支持媒体来源、文件名及复核状态筛选、分页、详情和失败重试；路由 query 保存筛选状态，来源页通过 `sourceId` 深链接跳转。歌曲查询的迟到响应不会覆盖新的筛选结果。空库引导前往媒体库扫描，不使用演示数据。

## 元数据刮削

歌曲行可打开候选审核弹窗，勾选歌曲可进入批次页，歌曲管理顶部的“元数据刮削”进入平台设置及全库批次。`modules/metadata/` 维护界面、API 和类型，路由 `#/library/songs/metadata`，受管理员登录保护；默认不启用平台、不自动写入，真实状态由后端保存。进度按需轮询，离开页面停止；重新打开读取最近批次。详情同时保留文件名解析证据，已确认字段优先展示，失效结果标明文件变化。见[元数据刮削](../../docs/metadata-scraping.md)。

批量刮削可在平台设置中配置每首完成后的随机等待范围（默认 3～8 秒，允许 2～300 秒，含端点；最大值不得小于最小值）。设置持久化且保存时暂停活动批次，续跑使用当前间隔；等待不占用数据库连接。同一平台请求仍保持串行及至少 1.5 秒启动间隔；HTTP 429 会触发该平台至少 60 秒冷却，期间拒绝新请求，失败项可稍后手动重试。单曲搜索也受平台冷却约束，批量随机等待只约束后台批次。随机间隔用于平滑流量，不能保证避免限流或自动化识别。

歌曲列表使用独立搜索区、分页表格及可选每页条数；歌曲位置页面使用卡片，来源列表 API 仍保留名称/地址、类型、方案筛选能力，查询使用 ID 分页后延迟关联和筛选排序联合索引。深分页成本与包含搜索边界见[列表查询说明](../../docs/library-search.md)。

媒体来源添加/编辑支持定时扫描开关及标准五段 cron（上海时区）；配置与下次触发持久化，同来源扫描中跳过，停机遗漏不逐次补跑。使用及 API 字段、调度限制见[定时扫描](../../docs/media-scan-schedule.md)。

单曲元数据已使用独立双栏审核工作台，支持字段编辑、受管 JPEG/PNG 上传、平台封面搜索及统一确认应用；旧批量审核入口保持独立。新增接口、资源备份、幂等与版本校验规则见[单曲审核](../../docs/single-song-review.md)。

批量工作台已统一整体进度：total/completed 均包含跳过项，新批次持久化跳过明细，旧批次仅汇总并提示。新增批次内搜索/排序、可信度审核提示及按状态操作，自动写入和限流规则不变。接口兼容说明及统计定义见[批量工作台](../../docs/batch-metadata-workbench.md)。

歌曲分类位于 `/library/classification`，包含词表维护、模型配置、输入预览、分类任务、人工审核与变更撤回；歌曲列表支持分类筛选和批量打标。详见[分类说明](../../docs/song-classification.md)。


歌曲列表对文件名解析“待复核”的歌曲显示主按钮“去复核”，详情中也提供入口，均复用现有单曲元数据审核工作台，可手工编辑或搜索候选，勾选字段后确认应用。完整匹配歌曲保留“元数据刮削”入口。元数据确认仍保存到独立覆盖层，文件名解析状态及待复核筛选语义不变；工作台明确说明这一区别，不修改原媒体。


歌曲筛选区的分类筛选使用可搜索、多选、可清空的下拉框；选中标签折叠显示，避免原生多选列表撑高筛选区。筛选控件居中对齐，窄屏换行，查询与重置行为不变。


## 管理端在线播放

歌曲列表行内操作统一为按钮，新增“在线播放”，在带原生控件的视频弹窗中播放当前歌曲。关闭弹窗或离开页面移除 video 元素以停止读取；错误时可重新加载。

`GET /api/v1/media-songs/{id}/video` 与 HEAD 复用管理员 Cookie 会话，未登录返回 401，不提供公开媒体 URL。支持单段 Range（起止、开放结束、后缀范围），本地响应 200/206/416 和 Content-Length/Content-Range；非法范围或多范围返回 400。所有流响应禁止缓存。本地解析真实路径并限制在来源目录内，失效文件或越界符号链接返回 404。

WebDAV 使用保存的地址和加密凭据在服务端发起 GET/HEAD，转发 Range，不把凭据或远端地址返回浏览器。采用 10 秒连接、30 秒读取空闲超时，流式传输，不落盘、不完整缓冲；连接随响应结束/客户端断开清理。上游忽略 Range 时保持 200，拖动能力取决于上游；不跟随 3xx（返回 502），需要支持直接读取的 WebDAV 服务，OpenList 等返回下载跳转的配置需调整，否则暂不能播放。认证/读取错误返回不含远端细节的 502。

只播放原始音视频，不调用 Python、不转码、不创建队列或电视会话。浏览器能否解码取决于容器与视频/音频编码，MP4/WebM 也不保证所有编码都能播放，MKV/AVI 等可能不可播放。Nginx 对视频接口关闭 proxy_buffering/proxy_cache，避免视频临时文件与额外等待；代理读取空闲超时为 60 秒。真实 NAS、WebDAV 提供者、浏览器编码兼容性仍须单独验收。


## 音频文件扫描与在线播放

本地目录与 WebDAV 文件名扫描统一支持 MP3、FLAC、WAV、M4A、AAC、OGG、OGA、Opus、WMA、AIF、AIFF、APE，扩展名不区分大小写，沿用现有解析方案提取歌名和歌手。扫描只建立文件名索引，不读取音频内容或内嵌标签；新增格式需重新扫描才会进入歌曲列表，现有扫描数量限制不变。

“在线播放”按扩展名选择音频/视频控件。音频复用已鉴权的 GET/HEAD `/api/v1/media-songs/{id}/video`（为兼容保留原路径），返回 audio/* 媒体类型，沿用 Range、后端 WebDAV 代理、凭据保护与关闭停止加载。音频失败可重试，切换或关闭时移除旧媒体元素。不提供转码，扩展名可入库不保证浏览器能解码；WMA、APE 等通常需要其他播放器。WebDAV 下载重定向限制不变。
