# SingVerse 网页前端

工程名 `singverse-frontend`，统一维护亲友点歌网页与NAS管理网页。Vue 3 + TypeScript + Vue Router 4 + Vite + Element Plus，采用多页面入口；亲友侧提供 Vue 扫码加入、曲库分类/点歌、已点与授权遥控，管理侧包含概览、系统状态、真实健康检查及失败重试。

## 目录与入口

```text
singverse-frontend/
  party/index.html            亲友入口 /party/，加载 src/party/main.ts
  src/party/                 亲友应用、独立 Bearer 请求、封面及样式
  public/party/assets/welcome.css   保留旧静态资源兼容路径
  admin/index.html            管理入口 /admin/
  src/admin/
    main.ts                   管理端启动
    App.vue                   语言 Provider 与布局入口
    app/                      路由注册/守卫、布局、全局样式和 404
    core/auth/                跨业务共享的认证请求、账号状态和会话查询
    core/hosting/             根路径与 /admin/ 的入口挂载路径工具
    modules/
      auth/                   登录与 MFA 验证页面、路由
      overview/               概览页面、路由
      system-status/          健康 API、健康卡片、状态页和路由
      system-parameters/      改密与 MFA 设置页面、路由
      media-library/          媒体库 API、类型、页面和路由
      filename-parser/        共享规则维护、方案组合/预览、类型、API 和路由
    shared/http/              通用同源只读 HTTP 客户端和错误类型
  tests/                      前端行为测试
  vite.config.ts              同一工程的两入口构建
  dist/                       两入口共享的完整静态产物，不提交
```

亲友入口 `/party/` 与管理入口 `/admin/` 共用一个工程、依赖锁文件及构建命令。管理页面使用 `/admin/#/overview` 和 `/admin/#/system`；管理页有登录守卫，后端独立强制授权；新增系统管理→系统参数（改密与MFA）。当前没有配对、点歌、队列、设备或播放业务，不使用模拟数据冒充真实状态。

## 开发与检查

需要Node.js 22.19+（22 LTS，或工具支持的24/26系列）与npm。依赖以package-lock.json为准，不需要全局安装Vite。

```sh
# 仓库根目录
make frontend-setup
make frontend-dev
# 另开终端构建前端、启动Java
make frontend-build
cd services/singverse-java-backend
./mvnw spring-boot:run
```

开发亲友入口 `http://127.0.0.1:5173/party/`，管理入口 `http://127.0.0.1:5173/admin/`，均由Vite本地提供。`/api`默认代理至 `http://127.0.0.1:8080`。使用其他开发后端时执行 `SINGVERSE_DEV_BACKEND=http://127.0.0.1:8081 make frontend-dev`；该配置仅用于开发代理，不写入浏览器产物。

```sh
make frontend-check   # vue-tsc、两个入口的生产构建
(cd services/singverse-frontend && npm test) # 全部 Vitest 行为测试
make frontend-build   # 类型检查及生产构建
make web-check        # 构建后实际HTTP验证亲友和管理两个入口、JS/CSS
make java-backend-test # 构建前端、Maven verify并打包JAR
```

`npm run preview`可在 `/admin/` 和 `/party/` 预览完整静态产物，不代理后端；健康联调使用开发代理或Java真实托管。开发和预览只监听回环地址。直接用file协议打开源码HTML不能运行Vite模块。

## 静态交付与未来Go

一次构建产出完整的dist：party/index为亲友页面，admin/index为管理页面，构建JS/CSS在assets，亲友样式在party/assets/welcome.css。Java Maven将整个dist复制到target/classes/static并打入JAR，不向Java源码目录生成文件；缺少任一入口时明确失败。直接执行Maven前也需make frontend-build，Maven不会自动更新已有产物。

生产不需要Node进程或CDN；Docker交付使用Nginx前端容器，执行根目录 `make docker-up` 即可联合构建并启动Java，访问 http://localhost:18080/ ，详见[Docker说明](../../docs/docker.md)。未来Go继续在根路径托管同一完整dist，并保持同源API、HTTP状态和授权语义，无需重写Vue工程。当前调用 `/api/health` 和 `/api/v1` 账号/MFA接口，API适配层强制请求带 `/api` 前缀；账号契约已建立，后续业务按[API约定](../../contracts/openapi/README.md)扩展OpenAPI。浏览器不直连数据库或Python内部服务。

详见[托管契约](../../contracts/frontend-hosting.md)。当前验证根路径部署，额外反向代理前缀需要同时调整资源、路由、API和服务挂载。网页检查不代表Android/iOS微信扫码、NAS部署或Go实际运行已验收。

## Nginx根路径管理

Nginx对外根路径直接提供管理页面，点歌页使用 `/party/`。构建资源通过 `/assets/` 独立提供，管理hash路由按实际访问地址确定基址，因此同一份产物可在根路径或 `/admin/` 打开。Nginx配置及Docker复制路径见[后端Nginx说明](../singverse-java-backend/nginx/README.md)。未来业务请求统一使用 `/api/v1`，代理保留 `/api` 前缀。

## 媒体库管理

管理侧 `#/library/media` 通过“曲库管理 → 媒体库”进入。以卡片展示少量本地目录和 WebDAV，不再显示筛选栏与分页表格；超过 100 个来源可继续加载。统一添加入口选择来源类型，本地目录通过服务端文件夹选择器选择，WebDAV 填写地址与可选凭据。名称留空时自动生成；定时扫描和解析方案位于“更多设置”。扫描完成留在当前页，可点击“查看歌曲”进入对应来源。本地结果保留到离开页面，WebDAV 后台任务可恢复。详见[媒体库说明](../../docs/media-library.md)。

## 模块边界

采用按业务聚合的目录，每个 `modules/<业务>/` 自己维护 `routes.ts`；需要时在内部增加 `api/`、`views/`、`components/` 和 `types.ts`，不预建空目录。`app/router/index.ts` 负责组合路由、登录守卫和页面标题；`app/layouts/AdminLayout.vue` 负责导航及管理外壳。现有 hash 路径、菜单和双入口构建保持不变。

页面调用本模块 API 适配器；跨模块账号状态和带 CSRF 的业务请求由 `core/auth` 提供。`shared` 只放通用能力，不引用业务模块或应用入口。模块不反向依赖 `app` 中的布局和路由实例；入口挂载路径工具归 `core/hosting/`，供路由和系统状态页复用。概览复用系统状态模块的健康卡片，避免复制健康请求与展示逻辑。测试引用实际所属模块，移动源码时同步更新 mock 路径。

当前没有为分包增加状态管理依赖、独立 npm 工作区或新的构建入口；新增页面沿用模块结构即可。

## 解析规则与解析方案

“曲库 → 解析方案”（`#/library/filename-parser-profiles`）是日常使用的唯一主路径，页面按“填文件名 → 挑格式 → 保存”四步组织：第 1 步输入媒体文件名并点“找出能识别的格式”，一次 `POST /profiles/preview` 携带全部内置格式候选，按返回的逐条 `attempts` 判定哪种命名格式能识别；第 2 步把内置格式渲染成卡片墙（`button.format-choice`），标出能用、只认出一半、识别不了、已在方案里，点一下即追加为成员、再点移出，不再使用铺满页面的系统下拉；第 3 步是方案名称与保存；第 4 步“我要自己排顺序、启停，或用自定义格式”折进 `<details class="profiles-advanced">`，保留原有序成员列表、启停、`添加已有规则`（此处选项已收窄为非内置定义）、`解析当前方案` 与完整预览面板。主区不出现“规则”一词，用户可见名词统一为“格式”。检测只在点击时发起，不自动触发；改文件名只把旧检测结果标记为过期。方案保存无需示例命中；切换/离开/刷新保护未保存草稿，成员或输入变化标记旧预览，迟到响应丢弃，冲突时“加载最新配置，保留草稿”并标明失效引用。

“曲库 → 解析规则”（`#/library/filename-parser`）降级为高级页，只维护单条自定义定义和引用情况，新增/编辑直接编译校验保存；内置定义只读、可复制，改由方案页的格式卡片提供，页面顶部明确提示平时不需要来这一页并给出返回主路径的链接。方案复制不复制定义；共享规则修改影响所有引用方案。默认方案可改名和清空、不能删除，引用中的规则不能删除并列出方案链接。旧路由和三个旧 API 保留兼容，新数据按 schemaVersion=2 保存，媒体来源可绑定完整方案，本地扫描会使用已保存的启用成员顺序提取并保存歌曲数据。详见[规则与方案说明](../../docs/filename-rules.md)。

## 管理页面布局与视觉主题

全站采用暖白背景、白色面板、深灰文字和青绿色强调色。`src/admin/app/styles.css` 是管理端全局样式入口，应用变量统一使用 `--sv-*`，Element Plus 通过 `--el-*` 映射到同一套主题。亲友欢迎页在 `public/party/assets/welcome.css` 中维护独立的同品牌浅色样式；不使用外部字体或 CDN。

侧栏按顺序提供“概览、曲库管理、文件名解析、系统设置”四个一级入口。曲库管理依次包含全部歌曲、歌手库、歌单管理、歌曲分类、媒体库、元数据整理；文件名解析包含解析方案和自定义规则；系统设置包含服务状态和账号与安全。当前页面所属分组自动展开，同一时间只展开一个分组，默认展开曲库管理，面包屑跟随分组与菜单名称；原有页面 URL 保持兼容。顶栏包含面包屑、亲友入口和账号菜单。768px 及以下侧栏收为抽屉，带明确的导航按钮、遮罩与 Escape 关闭操作，切换页面后自动收起。概览展示曲库工作入口、整理引导和真实服务健康，不展示虚构统计。

歌曲页桌面采用紧凑列表，手机采用卡片；支持关键词、来源、多选分类标签、待复核及未分类筛选，路由保留筛选和分页参数。统计卡明确标注为本页统计。批量模式支持全选本页和清空选择，底部操作栏预留正文空间；详情提供播放、元数据编辑和分类编辑入口。有效的已确认歌名和歌手优先展示。

解析方案采用左侧方案列表与右侧步骤流，格式以可点击卡片展示选中、可识别及旧结果状态。分类、刮削、来源配置、账号表单和各类审核弹层共享浅色组件主题。全局主按钮样式不覆盖 plain 按钮；确认框限制为 440px 并适配手机宽度，放弃审核时以绿色“继续审核”和浅红“放弃修改”区分操作。单曲工作台不再显示顶部“文件名解析待复核”的说明块，保留既有未保存保护、请求竞争保护与字段确认语义。密集表格在窄屏保留内部横向滚动；单曲审核在手机改为纵向内容滚动，操作页脚保持可用。

视觉验收使用 1440×900、768×1024 和 390×844 三种尺寸。截图为本地产物，不进入源码或 Docker 构建上下文；实际结果与未验收范围见[验证记录](../../docs/verification.md)。

## 歌曲管理

“曲库管理 → 全部歌曲”（`#/library/songs`）由 `modules/song-management/` 维护，集中展示本地目录及 WebDAV 扫描保存的歌曲，调用同源 `GET /api/v1/media-songs`。标题区采用紧凑标题和“整理元数据/管理来源”轻量入口，搜索、来源、分类集中在筛选面板；桌面搜索区（含搜索按钮）限制为380px，来源和分类合计限制为420px；移除快捷筛选整行。有筛选条件时同一行提供“重置筛选”，统一清空文件名、来源、标签及旧链接中的复核/未分类条件，保留每页数量并返回第一页。支持媒体来源、文件名及复核状态筛选、分页、详情和失败重试；路由 query 保存筛选状态，来源页通过 `sourceId` 深链接跳转。歌曲查询的迟到响应不会覆盖新的筛选结果。空库引导前往媒体库扫描，不使用演示数据。

桌面使用歌曲明细表，默认展示歌曲/歌手、已确认的专辑与发行日期、平台时长、分类标签、格式/大小、来源路径以及独立的文件名解析和元数据状态。“显示列”可切换解析细节与扫描/修改时间，支持恢复默认列及紧凑显示；这些展示选项在当前页面内生效。歌曲名及操作列固定，较窄屏幕在表格内横向滚动；手机改用信息卡片。表格不限制高度、不提供内部纵向滚动，每页 20/50/100 首按接口实际返回数量完整展开，统一随页面滚动；列表顶部和底部均可调整每页数量。紧凑模式收紧行距，并将歌曲编号合并到歌手行，减少单行高度。详情抽屉补充已确认元数据与完整分类。平台时长不代表媒体探测时长，解析清晰度标签仅来自文件名。未确认或过期元数据不展示为有效值，未知文件大小/时间不填零。列表总数、当前页范围及本页统计分别标注；批量操作使用表格上方的页内工具栏，不浮动遮挡歌曲或助手；未选择时禁用批量动作，选中后启用，支持全选本页、清空和退出。批量选择限本页，翻页或重新查询清空选择，筛选与分页继续保存在 URL。搜索沿用后端文件路径匹配，不搜索仅存在于确认元数据中的歌名或歌手。

歌曲详情抽屉采用封面概览：顶部集中展示有效封面、歌名、歌手、专辑、格式/时长/来源和播放、编辑操作，图片不可用时显示占位图。发行日期、语种和版本只显示已知值；缺失专辑不重复列空字段。歌词直接置于卡片，保留换行、支持滚动，LRC 时间标记仅在展示层去除；不修改已保存的歌词或实现播放同步。分类用标签展示，文件路径、扫描/修改时间、提取统计及维护操作默认折叠到“文件与技术信息”。封面和歌词共用原有缓存详情请求，优先显示有效已确认封面，避免覆盖上传/人工选择；切歌后忽略旧响应。

## 元数据刮削

歌曲行可打开候选审核弹窗，勾选歌曲可进入批次页，歌曲管理顶部的“元数据刮削”进入平台设置及全库批次。`modules/metadata/` 维护界面、API 和类型，路由 `#/library/songs/metadata`，受管理员登录保护；默认不启用平台、不自动写入，真实状态由后端保存。进度按需轮询，离开页面停止；重新打开读取最近批次。详情同时保留文件名解析证据，已确认字段优先展示，失效结果标明文件变化。见[元数据刮削](../../docs/metadata-scraping.md)。

批量刮削可在平台设置中配置每首完成后的随机等待范围（默认 3～8 秒，允许 2～300 秒，含端点；最大值不得小于最小值）。设置持久化且保存时暂停活动批次，续跑使用当前间隔；等待不占用数据库连接。同一平台请求仍保持串行及至少 1.5 秒启动间隔；HTTP 429 会触发该平台至少 60 秒冷却，期间拒绝新请求，失败项可稍后手动重试。单曲搜索也受平台冷却约束，批量随机等待只约束后台批次。随机间隔用于平滑流量，不能保证避免限流或自动化识别。

歌曲列表使用独立搜索区、桌面列表/手机卡片及可选每页条数；媒体库页面使用卡片，来源列表 API 仍保留名称/地址、类型、方案筛选能力，查询使用 ID 分页后延迟关联和筛选排序联合索引。深分页成本与包含搜索边界见[列表查询说明](../../docs/library-search.md)。

媒体来源添加/编辑支持定时扫描开关及标准五段 cron（上海时区）；配置与下次触发持久化，同来源扫描中跳过，停机遗漏不逐次补跑。使用及 API 字段、调度限制见[定时扫描](../../docs/media-scan-schedule.md)。

单曲元数据已使用独立双栏审核工作台，支持字段编辑、受管 JPEG/PNG 上传、平台封面搜索及统一确认应用；旧批量审核入口保持独立。新增接口、资源备份、幂等与版本校验规则见[单曲审核](../../docs/single-song-review.md)。

批量工作台已统一整体进度：total/completed 均包含跳过项，新批次持久化跳过明细，旧批次仅汇总并提示。新增批次内搜索/排序、可信度审核提示及按状态操作，自动写入和限流规则不变。接口兼容说明及统计定义见[批量工作台](../../docs/batch-metadata-workbench.md)。

歌曲分类位于 `/library/classification`，包含词表维护、输入预览、分类任务、人工审核与变更撤回；模型服务、启用开关和请求间隔在 AI 设置独立管理；歌曲列表支持分类筛选和批量打标。详见[分类说明](../../docs/song-classification.md)。


歌曲列表对文件名解析“待复核”的歌曲显示“复核”按钮，详情中也提供入口，均复用现有单曲元数据审核工作台，可手工编辑或搜索候选，勾选字段后确认应用。完整匹配歌曲保留“编辑”入口。元数据确认仍保存到独立覆盖层，文件名解析状态及待复核筛选语义不变；工作台明确说明这一区别，不修改原媒体。


歌曲筛选区的分类筛选使用可搜索、多选、可清空的下拉框；选中标签折叠显示，避免原生多选列表撑高筛选区。筛选控件居中对齐，窄屏换行，查询与重置行为不变。


## 管理端在线播放

歌曲列表行内操作统一为按钮，新增“在线播放”，在带原生控件的视频弹窗中播放当前歌曲。关闭弹窗或离开页面移除 video 元素以停止读取；错误时可重新加载。

`GET /api/v1/media-songs/{id}/video` 与 HEAD 复用管理员 Cookie 会话，未登录返回 401，不提供公开媒体 URL。支持单段 Range（起止、开放结束、后缀范围），本地响应 200/206/416 和 Content-Length/Content-Range；非法范围或多范围返回 400。所有流响应禁止缓存。本地解析真实路径并限制在来源目录内，失效文件或越界符号链接返回 404。

WebDAV 使用保存的地址和加密凭据在服务端发起 GET/HEAD，转发 Range，不把凭据或远端地址返回浏览器。采用 10 秒连接、30 秒读取空闲超时，流式传输，不落盘、不完整缓冲；连接随响应结束/客户端断开清理。上游忽略 Range 时保持 200，拖动能力取决于上游；不跟随 3xx（返回 502），需要支持直接读取的 WebDAV 服务，OpenList 等返回下载跳转的配置需调整，否则暂不能播放。认证/读取错误返回不含远端细节的 502。

原始媒体接口继续直放；播放弹窗另通过 Java 协商 HLS 或兼容版本，浏览器不直连 Python，也不因预览创建电视会话。浏览器能否解码取决于容器与视频/音频编码，MP4/WebM 也不保证所有编码都能播放，MKV/AVI 等可能不可播放。Nginx 对视频接口关闭 proxy_buffering/proxy_cache，避免视频临时文件与额外等待；代理读取空闲超时为 60 秒。真实 NAS、WebDAV 提供者、浏览器编码兼容性仍须单独验收。


## 音频文件扫描与在线播放

本地目录与 WebDAV 文件名扫描统一支持 MP3、FLAC、WAV、M4A、AAC、OGG、OGA、Opus、WMA、AIF、AIFF、APE，扩展名不区分大小写，沿用现有解析方案提取歌名和歌手。扫描只建立文件名索引，不读取音频内容或内嵌标签；新增格式需重新扫描才会进入歌曲列表，现有扫描数量限制不变。

“在线播放”按扩展名选择音频/视频控件。音频复用已鉴权的 GET/HEAD `/api/v1/media-songs/{id}/video`（为兼容保留原路径），返回 audio/* 媒体类型，沿用 Range、后端 WebDAV 代理、凭据保护与关闭停止加载。音频失败可重试，切换或关闭时移除旧媒体元素。不能直放时可使用兼容播放或离线版本；实际支持取决于 compute 工具与源编码。WebDAV 下载重定向限制不变。


## AI 配置中心

系统设置按“AI 设置 → 服务状态 → 账号与安全”排列。AI 设置仅提供模型服务、搜索服务、功能配置三个页签，路由为 `/system/ai/models`、`/system/ai/search`、`/system/ai/features`，`/system/ai` 重定向模型服务。侧栏不增加第三层菜单，歌曲分类仍在曲库管理。

`src/admin/modules/ai-settings` 独立管理共享服务与功能绑定；分类模块仅读取兼容配置摘要并跳转到功能配置。多个服务可使用同一厂商，模型 ID 手填；Schema 和 JSON 模式显式选择。测试只请求已保存配置，普通生成、分类结构化输出及搜索查询分别验证。搜索结果只展示标题、链接、摘要及耗时，不抓取正文、不用于分类。

编辑密钥留空表示保留，读取接口仅返回 `hasKey`。厂商、协议或地址改变时必须重新输入或明确清除原密钥；被绑定的服务需先替换或解除绑定才可停用或删除。页面和表单离开时保护未保存修改，窄屏弹窗内部滚动。详见 [AI 设置](../../docs/ai-settings.md)。


AI 设置的功能配置新增独立 AI 助手页 `/system/ai/features/assistant`。可启用全局管理页右下角助手并选择宠物/聊天框形态；默认关闭、服务端保存，当前仅展示能力规划。宠物目录 `ai-settings/pets.ts` 独立于助手交互；本地 SVG 形象无需网络。对话和工具调用尚未开放，亲友 H5 不显示。


解析方案底部的“方案与保存”采用独立名称标签、保存状态和按钮布局，数量摘要显示启用/停用格式；高级配置提供有间距的执行顺序、添加规则和草稿预览区域。窄屏按钮与添加控件自动换行，不改变方案保存、排序及启停行为。


歌曲分类已按普通用户流程重做：开始分类负责选歌、选择分类内容和确认输入；分类记录集中处理进度、审核、重试与人工整理；分类词表独立维护标签。结果使用适配手机的歌曲卡片，确认时比较前后分类。保留原 songIds/task 查询参数、接口和全部业务保护；自动保存默认关闭，高级选项中显式开启。共享结果展示组件为 `ClassificationResultCard.vue`，页面样式单独放在模块 `styles/classification.css`。


歌曲分类的“选择歌曲 / 重新选择歌曲”均在当前页打开 `ClassificationSongPicker.vue` 弹窗。支持同源接口搜索、分页、选择本页、跨页勾选及 5000 首上限；列表内部滚动，搜索、分页和确认按钮固定可见。确认后更新兼容 songIds 查询参数并保留分类选项，取消只丢弃弹窗选择草稿。

AI 助手的宠物和聊天框入口支持鼠标/触屏拖动，移动超过6px才识别为拖动并抑制松手点击；位置限制在当前窗口内，缩放窗口或切换形态后重新约束。展开面板根据入口位置向上或向下显示。位置仅在当前管理页会话保留，刷新恢复默认入口位置。

歌曲复核展示以有效确认的核心信息为准：歌名和歌手均勾选确认、非空且元数据未失效后，列表/手机卡片显示“歌曲信息已复核”，操作改为“编辑”，本页统计计入已复核。仅确认专辑、时长或封面不解除原有复核提示。详情保留原始文件名解析证据，旧 status=REVIEW 查询仍匹配原始解析状态。

本地媒体库扫描读取音视频内嵌歌名、歌手、专辑、发行日期，文件字段优先，缺失字段回退已确认信息/文件名。全部歌曲标识“优先使用文件内嵌信息”，审核提示内嵌字段会被保留；需要修改这些字段时编辑原文件标签后重新扫描。WebDAV继续只按文件名索引，不下载媒体内容。

### 性能节点配置

系统设置顺序为 AI 设置、性能节点配置、服务状态、账号与安全。`/system/compute` 提供自动识别、独立部署、暂不使用三种模式；默认展示当前连接是否可用、地址和文件标签用途；随应用部署的服务自动连接，无需再次填写。点击“更换连接方式”才展开配置：连接其他设备、使用随应用服务、暂不使用。目录映射、密钥获取说明按需展开。独立部署支持加密凭据、最长根路径优先的媒体路径映射；新连接检查通过才保存并切换，失败保留原连接，并可明确选择仅保存离线配置。当前状态检查与编辑草稿分离，取消恢复原配置；离开未保存草稿有保护。客户端仅调用同源 `/api/v1/compute-node`，不直接连接 Python。配置只管理一个活动节点，不包含负载均衡或远程文件传输。

## 电视与亲友点歌

管理端 `#/system/tv-devices` 核对电视授权码并批准/撤销设备。每条待确认申请都有独立的六位数字输入框，保留前导零，支持回车提交；批准失败时保留输入供修改。亲友 `/party/` 使用 fragment 邀请链接，预览不加入，显式确认后在 sessionStorage 保存本场独立参与凭据；不复用管理员 Cookie。同一 H5 供微信及 App 网页容器使用。点歌超时保留原请求 ID，提示先核对队列再重试；锁队、撤权和散场均由 Java 强制检查。视觉采用暖白与珊瑚橙。微信/App 真机与 NAS 网络另行验收。


### 分类封面

管理入口「歌曲分类 → 分类词表」可点击缩略图或“上传封面/更换封面”，选择图片后预览并显式保存；移除需要确认。不需要启用 AI。新标签先保存到词表，再上传封面。建议16:9横图、主体居中，JPEG/PNG最多2,000,000字节、单边不超过4096像素；后端重编码为最长边1280像素JPEG并移除附加信息。预览为居中裁切，与TV的分类卡片一致。

上传/移除使用管理员Cookie及CSRF，封面有独立的coverVersion防止覆盖其他管理员窗口的新图片；409时关闭弹窗并点“刷新词表”重试。选择后未保存的图片不生效，上传中阻止重复提交，离开组件取消请求。封面不改变标签名、启用状态或歌曲归类。TV进入分类或约30秒刷新可见更新；标签停用后TV不显示封面，管理页仍可管理。

## 自动歌手库

扫描后按歌曲有效署名自动生成，不再人工建档/关联。管理端歌手详情可打开歌曲编辑器订正歌手，NAS 覆盖值优先于文件标签并在重新扫描后保留；恢复扫描值需确认。首次后台从网易云/QQ 核对歌曲并取真实歌手头像，失败有限重试，无可靠匹配保留占位。上传图片优先，移除后暂停自动补图。TV 自动展示同步结果和受权图片，保留返回焦点。迁移 `202610290008`，新增接口、来源与状态见 OpenAPI 和 [自动歌手库说明](../../docs/artist-library.md)。

歌手卡片及背景上传预览优先显示独立背景图；只有头像时由浏览器将头像模糊、调暗并裁切为横幅，仅用于展示，不写入背景图片；两种图片都缺失时显示渐变。上传界面明确标出头像生成的预览。

## 共享歌单

「曲库管理 → 歌单管理」及歌曲管理快捷入口支持手动选歌、排序、编辑/删除与 AI 辅助创建。AI 选择已配置启用模型，最多从 500 首候选中推荐 1～50 首，先预览并明确采用，再保存；无模型时可手动创建。复用歌曲选择器，歌单上限 500 首，跨页保留选择。实现与接口见 [歌单说明](../../docs/playlists.md)。

性能节点页面新增“转码与硬件加速”，通过 Java 读取/测试/保存计算节点执行配置，支持恢复部署默认与按编码器查看探测结果；所有变更继续使用管理员会话和 CSRF。

硬件页面以独立设置区、当前生效摘要和节点能力表展示；当前方式优先，其他平台和部署说明默认折叠。素材试跑后的硬解、零拷贝、GPU 色调映射分别标记，CPU 仅显示软件处理；播放弹窗显示实际流水线。未试跑硬件显示“待验证”，不会沿用编码器存在这一条件宣称全链路可用。

## WebDAV 扫描与内嵌元数据

WebDAV 扫描按路径增量更新，卡片显示新增、复用、待确认删除、下架数量。缺失文件需间隔至少 30 分钟的两次完整成功扫描确认；突然空库保留索引，在“整理与分享”中单独确认全部下架，缓存保留 30 天。

“整理与分享”默认只展示歌曲信息、分享曲库、导入曲库三个操作区。点击“完善歌曲信息”直接开始后台处理，可一键暂停/继续；本地来源提供查看歌曲。空库提供扫描入口。试读样本、重新扫描、访问组、代理地址、增量分享及单独下载分包收进默认折叠的“高级选项”，不展示步骤导航、文件同步数量、读取流量统计或内部任务状态。

点击“导出分享包”后，由后台等待文件保存并生成快照，界面显示“正在准备”；关闭窗口不影响后台任务，完成后只提供“下载分享包”和重新导出。每包最多 5000 首、32 MiB 的拆分由系统完成。选中收到的整套 ZIP 后立即导入，无需先解压或再次点击开始；也支持按文件名顺序选择多个分包。整套上传最多 8 GiB，服务逐个处理有界分包，中断后重新选择即可继续，已有歌曲和人工订正不会覆盖。

本地和 WebDAV 的刮削采用、编辑及内嵌提取结果自动保存到统一服务衍生目录，原媒体及旁边目录保持只读。暂不可用的封面后台补齐，不阻塞正文保存或分享；较大封面自动缩小到受控附件大小。仅需要用户处理的操作失败在主界面显示简短提示，其余状态收进高级选项。

行为测试位于 `tests/embedded-metadata.test.ts`，覆盖主按钮启停、隐藏技术细节、后台等待、选择文件即导入、样本缓存复用及空库确认。共享核心信息仍显示“共享信息待核对”，确认后解除提示。模拟与浏览器验证不能替代实际 OpenList/网盘风控验收。
