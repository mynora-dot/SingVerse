# 歌曲缓存混合淘汰与生命周期

适用于 Java 服务节点持久化的 WebDAV 原片块和实时 HLS，不管理媒体原件、用户收藏、播放历史或独立离线兼容版本。业务 SQL 统一位于 `mappers/transcoding/SongCacheMapper.xml` 与 `mappers/playbackhistory/PlaybackActivityMapper.xml`。计算节点继续只管理执行临时产物。

## 现状问题与修复

| 原问题 | 实现 |
|---|---|
| HTTP 获取、预取、续租写入 hits/access，无法反映真正播放 | 保留诊断字段，淘汰只读取播放历史及其可重建派生聚合 |
| 生命周期累计热门长期占满缓存 | 每次有效播放增量限幅，热度本身随时间减半；没有历史计数永久加分 |
| 最近低频歌曲容易被淘汰 | 24 小时硬保护与 24～72 小时软保护，真实最近播放独立占 40% |
| 原片 HTTP 结束后歌曲可能仍在播放/暂停 | 独立歌曲级占用；15 秒内续租，断联 120 秒后失效；暂停只续占用 |
| 同步清理阻塞起播和续租 | 独立单线程回收，冷文件校验/索引恢复使用有界 IO 线程；热播放只检查当前文件 |
| 删除文件到一半失败或索引提交失败 | 持久 DELETING/token、隔离改名、所有权标记最后删除、失败退避和重启恢复 |
| 原片整段预留导致过度淘汰 | 最大 32MiB 滚动窗口；配额不足可缩小至完整块，播放继续回源 |
| 预取因一次配额不足永久停止 | 等待清理代次变化或退避后续取；有效下一首目标受到歌曲级保护 |

## 事实与评分

TV、手机和管理端使用单调时钟累计实际播放，不以媒体 position 的差值估计。约每 5 秒及状态变化报告，暂停/缓冲约每 15 秒续占用。准备、暂停、缓冲和 seek 不计实播时长。独立伴奏不重复计数，手机本机作品回听不上报。发生时间和最后真实活动时间随快照冻结，重试不能改用接收时间续保护。具体协议、身份和时间校验见 [真实播放活动](song-activity.md)。

同一实例累计至少 30 秒，或完整播放不足 30 秒的短曲，计一次有效播放。TV/手机有效播放增加 H/F；管理员试听只更新真实最近使用与占用。重新点播、重唱及完整单曲循环产生新实例；seek、切轨、兼容回退与 A–B 循环保留实例。历史有效时间、事件序号和事务内聚合确保重复、乱序与重试不重复计次。

全部时间为 UTC 毫秒，“天”指连续 86,400,000 毫秒。

```text
H(t) = clamp(h,0,1) × 2^(-(t - heatUpdatedAt)/14天)
每次有效播放：h = min(1, H(t) + 0.05)
R = 2^(-(t - lastPlayedAt)/7天)
F = min(1, ln(1 + playCount7d)/ln(21))
Score = 0.4H + 0.4R + 0.2F
B = 0.15 × clamp((72小时 - 距最近播放时间)/48小时, 0, 1)
Priority = Score + (1 - Score) × B
```

缺少播放记录时 H/R/F 为零。H 在每次累积时限幅；旧缓存 `hits` 不转换成有效播放。有效历史作为事实源，派生数据可重建；旧历史使用 `started_at` 兼容口径分批准备，再按有效时间顺序聚合。普通顺序事件增量更新，迟到的有效事件仅重算该歌曲已经应用的历史，保证热度封顶后仍与按发生时间处理一致。回填未就绪时保守暂停普通回收，播放继续；单项显式覆盖近期保护可继续执行其它硬保护检查。

核心评分代码为 `CacheEvictionPolicy.score/decay/recent`；生产回收实际调用 `SongCacheService.rankCandidates`，每条候选只计算一次评分：

```java
double h = decay(heat, heatAt, now);
double r = lastPlayedAt == null ? 0 : Math.pow(2, -age(now, lastPlayedAt) / (7.0 * DAY));
double f = Math.min(1, Math.log1p(Math.max(0, plays7d)) / Math.log(21));
double score = clamp(.4 * h + .4 * r + .2 * f);
double bonus = lastPlayedAt == null ? 0 : .15 * clamp((3.0 * DAY - age(now, lastPlayedAt)) / (2.0 * DAY));
double priority = clamp(score + (1 - score) * bonus);
```

按 Priority 升序淘汰，同分依次按 EVICT/COLD/WARM/HOT、大小降序、最近播放升序和稳定 ID 排序；大小只作同分决胜。生命周期：HOT 为最近 7 天至少 3 次有效播放且最近活动不足 7 天；WARM 为其余最近 30 天有播放；COLD 为 30～60 天；EVICT 为至少 60 天。未播放歌曲以该歌曲最早缓存创建时间计算生命周期，但不生成播放分数。60 天前的热门歌曲照常进入候选。

## 保护与回收

普通 POLICY 和 CLEAR 排除所有以下情况：

- 当前缓存读者和歌曲级活动播放/暂停/缓冲租约。
- 正在接收的原片或 HLS 下载，及该歌曲的其它缓存变体。
- 歌曲级手动固定，覆盖现有及将来变体。
- 最近 24 小时真实播放。
- 队列仍选中的下一首预取目标，包括已经预取完整的目标。

固定不会下载缺失内容，也不等同于收藏或独立离线下载。取消固定使用独立 revision，统计更新不会覆盖用户偏好；固定记录没有曲库行级联外键，不因扫描替换行而丢失。

单项 DELETE 默认遵守全部保护；须先取消固定，显式 `confirmRecent=true` 才可覆盖近期保护，活动播放、下载和有效预取保护始终不可覆盖。认领后再开始的新播放按未命中回源，不能借出 DELETING 条目。

默认高水位 90%、低水位 75%，相对于缓存预算。整数配置满足 `1≤low<high≤100`；NAS 最低磁盘空闲量独立计算。用量包含已发布、正在预留、损坏文件残留和未完成删除的数据，已预留的空间不会再次当成待申请空间计入。有效 `bytes/cachedBytes` 不包含损坏残留；额外占用由持久 `residue_bytes` 记录并计入总用量，实际替换或删除之后才释放。达到高水位或申请容量不足时投递单线程任务，重复触发合并并保留一次后续唤醒；受保护或失败时结束，默认冷却 60 秒。

回收到低水位且满足当前申请/磁盘约束后停止；候选不足时报告“目标未达”，只有确实不能容纳申请或低于磁盘余量才报告“空间不足”。不突破保护规则。MANUAL 不自动清理；两种模式配额不足都继续播放，原片回源或使用当前 compute HLS 资源。

## 文件和索引一致性

`claim` 在短事务内取得歌曲 profile 写锁，重新读取固定、实际播放和租约；与读者/下载登记共用短注册锁。MySQL 使用当前读/适当隔离，避免 REPEATABLE READ 旧快照绕过新保护。事务提交后仅投递后台任务。

回收步骤为：

1. ACTIVE 原子认领为 DELETING，持久保存随机 token。
2. 验证所有权与路径，以原子改名隔离到 `.deleting-{id}-{token}`。
3. 后台递归删除，所有权标记最后删除；不跟随符号链接。
4. 文件删除完成后，事务删除缓存租约和索引，才减少已承诺用量。

失败保留 DELETING、错误和默认 60 秒重试时间，继续处理其它候选。重启恢复认领前/改名后/部分删除/文件已删但数据库未提交各阶段；旧未完成清理任务标为 INTERRUPTED。未知目录不当作普通缓存删除。任务日志保留 7 天，日志不包含来源凭据和实际媒体路径。

原片只发布完整 2MiB 块，尾块按总长度截断；冷恢复扫描放到有界 IO 线程并校正有效块与残留索引，热读取只检查当前块。启动时在后台逐条核对物理占用，不能让一个条目的截断抵消另一个条目尚未入库的块；准备完成前直接回源。HLS 发布前校验全清单、长度、摘要与播放列表引用，热读取/续租不遍历所有片段。清理候选为轻量 SQL 投影，批量关联播放统计；管理列表先分页，只读取当前页元数据，不读取完整分片清单。

## 接口兼容

路径前缀 `/api/v1/transcoding/cache`，沿用管理员会话和 CSRF。

| 方法/路径 | 行为 |
|---|---|
| GET 空路径 | 保留 page/size，增加 H/R/F/score/priority/lifecycle、固定版本、保护原因、水位及用量准备状态 |
| PUT `/settings` | 保留 maxBytes/policy/ttlHours/revision 四字段；水位省略时保留现值，旧自动策略规范化 HYBRID |
| GET `/pins` | 固定歌曲分页列表，包括暂时没有缓存的歌曲 |
| PUT `/songs/{songId}/pin` | `{pinned,revision}`，冲突 409；已经认领删除时不能重新固定该缓存 |
| POST `/cleanup-jobs` | `{mode:POLICY|CLEAR|DELETE,entryId?,confirmRecent?}`，返回 202 及任务 ID |
| GET `/cleanup-jobs/{id}` | 查询计数、实际释放量、跳过原因、失败、目标、空间缺口和最终状态 |
| POST `/cleanup-jobs/{id}/cancel` | 可取消排队/执行任务；已认领文件完成当前删除后停止，保持索引一致 |
| POST `/clear` | 复用后台流程，保持 removed/skipped 返回兼容 |
| DELETE `/{id}` | 保持 204；新增 confirmRecent 默认 false，受保护返回 409 |

设置、固定和任务并非共用 revision。任务状态为 QUEUED/RUNNING/CANCELLING/SUCCEEDED/PARTIAL/BLOCKED/FAILED/CANCELLED/INTERRUPTED。完整字段以 [OpenAPI](openapi/singverse.openapi.json) 为准。

## 数据迁移和验证入口

SQLite/MySQL 各使用 `202611070001_initial_schema.sql` 从空库一次创建完整结构，包括水位、profile 固定/热度、幂等实例/租约、有效计次时间、删除日志及分页/历史/待删索引。默认策略直接为 HYBRID，设置 revision=0；空库播放统计直接就绪。此前增量迁移已合并删除，不提供旧数据库升级路径。验证入口及数据隔离见[数据库说明](../database/README.md)。

针对性用例覆盖评分半衰/边界、近期保护、固定/下载/暂停/预取保护、容量水位、重复触发、取消、并发保护重检、四阶段恢复、删除失败/数据库回滚、原片滚动预留/容量恢复和真实 HTTP 授权。`CacheScaleTest` 用 1 万/10 万轻量记录测量真实 XML 查询、生产排序、20 条分页与热文件检查；只创建一份微小 HLS 夹具，不冒充真实 NAS 吞吐基准。

实际本轮结果、制品及真机限制单独记录于 `docs/verification.md`。前端完整测试、Java/SQLite、隔离 MySQL、TV/手机检查及 Java/Python 联动按各自工具链执行；本机编译与仪器编译不代表实体 NAS/TV/手机验收。
