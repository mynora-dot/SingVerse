# 后台任务中心

管理员从「设备与服务 → 后台任务」进入 `#/system/tasks`。首页只展示每次操作的批次，默认查看未完成批次，可切换最近 30 天的历史或全部记录，按类型、整批状态、名称、关联歌曲或子任务编号筛选；每页默认 20 条。服务端在分页前按运行中 → 取消中 → 排队中 → 已暂停 → 等待开始 → 已结束排序，同级按创建时间、编号倒序；关键词匹配子任务时按批次去重。点击进入 `#/system/tasks/:id`，简洁概览下直接展示任务明细。明细同样运行优先，可筛选和分页；单任务可继续打开详情，返回批次或列表恢复页码和筛选。

## 覆盖范围与结果含义

| 业务 | 记录方式 | 详情与跳转 |
|---|---|---|
| 本地 / WebDAV 扫描 | 手动和定时扫描均记录；保留原有执行接口与限制 | 扫描自身阶段、计数及结果摘要；实际产生的探测与快速识别归入同一批次，定位媒体来源 |
| 元数据整理 | 每个业务批次一条 | 已有逐曲结果分页；定位具体批次 |
| AI 分类 | 每个业务任务一条 | 已有逐曲结果分页；定位具体任务 |
| 音轨识别、伴奏生成 | 手动批量一条；独立单曲操作是含 1 项的批次；无扫描归属的自动发现按完整发现轮次和来源成批 | 批次深链接或对应歌曲的音频工作台 |
| 离线转码 | 每个离线任务一条，不含实时播放 | 歌曲详情中的兼容版本 |
| 缓存清理 | 手动与策略清理均记录 | 保留业务计数与已有的前 20 条失败信息；定位原清理任务 |
| 分享包导出 | 每个导出任务一条 | 已导出歌曲、分包数与业务原因；定位媒体来源 |
| 歌曲下载 | `LX_DOWNLOAD`，每个下载批次一条，复用逐曲状态与结果 | 排队、解析、传输、入库及失败提示；深链接 `#/library/downloads?tab=records&batch=...` |

不新增独立的文件标签提取、歌手抓图、模型下载、实时播放会话及内部维护记录。扫描不新增逐文件日志，其余任务只保存原业务已有的结果粒度。任务中心只读；暂停、续跑、取消、重试、审核等操作在相关业务页进行。

歌曲下载使用自身持久执行队列，任务中心仅投影。成功与已存在计为完成，失败、中断、取消单独统计；发布阶段仍属处理中，整批结束后按原任务中心策略保留快照。长期下载来源和实际歌曲文件不随快照过期移除。

元数据、分类和批量伴奏复用已有逐项结果，不同时重复展示子任务与结果两套列表；独立操作以原任务为唯一明细。总量明确时显示当前阶段百分比；扫描和自动识别链不计算整体百分比，扫描自身的阶段计数与进度单独保留。目录遍历、离线转码等没有整体分母的阶段显示实际计数或阶段，不估算百分比。伴奏分离的帧计数标为「当前阶段」，不表示任务整体完成。音频批次在子项真正探测或处理后显示运行中，全部等待时显示排队中；准备好的预览显示等待开始。

「处理完成」表示整批相关处理过程结束，可能有待审核、未写入或失败条目；待审核、识别不确定与已保存分别统计，已完成批次有失败项时显示部分完成。历史缺少开始或结束时间时保留空值，并明确提示无法还原准确耗时。

## 扫描与跨阶段归属

保存索引时，在同一事务按歌曲与实际素材指纹登记处理范围；WebDAV 只纳入本次暂存索引实际发现的歌曲。处理范围封口、扫描自身结束、探测到快速识别的全部判断和任务均结束后，整批才进入终态。成功探测后等待下一次发现来判断或创建快速识别时，范围仍为待发现，批次显示排队，结束时间为空。

沿用业务的无需处理、已确认音轨、非双音轨及模型升级一次性重试判断。未配置节点或未启用阶段登记跳过；已纳入的阶段因节点暂不可用而等待时显示排队与等待原因。已存在的任务仅增加关联，保留原批次与任务编号；同一批次与同一任务只计一次。新建任务与归属记录在同一事务提交，回滚不留下散任务。扫描后素材改变或歌曲删除时，保留范围与快照并记录中断原因。

自动发现每次遍历完整候选库形成一个发现轮次，各来源分别成批；跨页和后续阶段沿用归属，不按每次轮询拆批。启动时封口上一次未封口的自动轮次，已登记的未结束范围继续核对。真实运行的子任务使批次显示运行；仅等待创建或排队则显示排队。失败、取消和中断与其他成功结果共同决定部分完成或对应异常状态。

## 刷新与关联对象

页面可见时每 2 秒刷新未完成列表及活动任务详情；请求失败保留上次成功结果，5 秒后重试。历史列表和结束的详情可手动刷新。切换筛选、任务或离页后忽略旧响应，页面隐藏时停止轮询，重新可见立即读取。

来源、歌曲或原业务记录删除后，独立任务快照继续保留；界面说明关联对象已移除或过期，并隐藏不可用的业务入口。任务中心不会恢复原业务数据，也不改变其保留期限。

## 记录、恢复与清理

Go 的 background 模块复用 `background_task` 保存批次概览，并分别保留原业务状态、阶段和时间以及批次聚合状态、子项统计和结束时间；`background_task_item` 保存已有逐项结果的精简快照。`background_task_relation` 保存可共享任务的批次关系，`background_scan_scope` 保存歌曲与素材指纹的处理准入及跨阶段状态，不保存逐文件扫描日志。记录以任务类型与业务编号唯一；同一业务任务续跑更新原记录，新建业务任务使用新的记录。本地扫描生成独立业务编号，维持同步调用。

业务模块在状态写入的同一 `store.DBTX` 内调用 `Project`、扫描范围登记等显式钩子，同步更新任务快照；失败时一并回滚，不另取数据库连接。本地扫描通过开始、进度、结束与范围钩子记录真实生命周期，客户端断开后仍记入终态。后台模块只维护展示记录，各业务保留自己的执行、并发、重试和取消规则。业务查询和写入 SQL 位于 `internal/background/sql/` 的嵌入文件。

未完成关系回填的旧记录不会先以散任务列入首页；旧批次按每页导入合并汇总，避免逐子项重复统计大批次。启动后按每批 100 条导入仍可读取的未完成任务及近期历史，每分钟核对未完成记录；逐项快照按最多 200 条分页读取。恢复遵循各业务自己的规则。优先回填音频业务中可确认的真实关系；旧散任务无法确认原操作时，按来源及类型收进明确标注「未记录原始批次」的历史归档批次，不猜测扫描归属，保留原编号与详情。本地扫描遇重启标记中断；原预览被业务清理后标记过期。旧记录没有保存的时间、明细和已被清理的历史无法补回，本地扫描历史从启用本功能开始积累。

整批结束后概览、已记录明细和范围保留 30 天；活动批次及其已结束子项持续保留。共享子任务仍被任何有效批次引用时继续保留。导入的旧任务没有结束时间时用其最后更新时间（若无则创建时间）计算期限，不伪造结束时间；历史归档批次继承子任务已有的最晚保留期限，迁移不会重新起算 30 天。未完成记录没有到期时间。清理每批最多 100 条，只删除任务中心的概览和明细，不删除歌曲、兼容版本、缓存文件或分享包。

SQLite 与 MySQL 在原有 `202611080001_background_tasks.sql` 之后新增 `202611090001_background_task_batches.sql`，保留现有数据库与任务编号，导入已确认的 parent 关系。应用启动仅应用未部署的增量迁移，不修改初始化基线，不需要清库。

## 管理员只读接口

| 接口 | 参数与响应 |
|---|---|
| `GET /api/v1/background-tasks` | `view=ACTIVE/HISTORY/ALL`（默认 ACTIVE）、`type`、`status`、`q`、`page=0`、`size=20`；返回 items/page/size/totalElements/observedAt |
| `GET /api/v1/background-tasks/{id}` | 批次标识、所属批次、childrenCounts、detailMode、批次状态与时间、operation 原业务阶段进度、等待原因、结果及业务入口 |
| `GET /api/v1/background-tasks/{id}/children` | `type`、`status`、`page`、`size`；运行优先的关联任务分页，counts 为未筛选的子任务状态；单独操作返回自身一项 |
| `GET /api/v1/background-tasks/{id}/items` | `status`（原明细状态）、`page`、`size`；返回分页精简快照与未筛选的各状态 counts |

`detailMode=ITEMS` 使用已有 `/items`；`CHILDREN` 使用 `/children`，页面只展示其中一种。`childrenCounts.total` 是实际任务/原生条目数，`queued` 另外包括等待阶段判断或创建的 `pendingDiscovery` 歌曲数，因此扫描不能据这些计数计算整体百分比。`id` 是任务中心编号，`businessId` 是原业务编号。页码从 0 开始，最大 1000000，页大小 1～100，关键词最多 200 字符，按字面搜索并转义 SQL 通配符。未登录返回 401，无效筛选返回 400，记录不存在或超过保留期返回 404。接口只读 Go 已保存的数据，不连接计算节点或媒体来源。

接口复用管理员 Cookie 会话鉴权，不接受 TV/亲友凭据。仅返回展示白名单字段，不返回业务原始配置、计算节点地址、媒体绝对路径或凭据；执行错误中的地址、路径及凭据形式会被隐藏。字段定义见 [OpenAPI](openapi/singverse.openapi.json)。
