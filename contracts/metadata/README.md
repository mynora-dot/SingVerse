# SingVerse 元数据存储标准 1.0

状态：本仓库实现的第一版公开资料语义。资料语义版本 `schemaVersion: "1.0"` 与共享容器版本 `version: 4` 分开演进。字段定义见 [字段字典](fields.md)，容器见 [v4 资料包](package-v4.md)，机器格式见 [JSON Schema](metadata.schema.json)。规范用“必须”“不得”“可以”表达约束。

## 身份与归属

所有资料对象使用小写 UUID 字符串；新对象生成随机 UUID。内部身份不由路径、歌名、平台标识或 ETag 推导。旧媒体 ID 保留。作品 WORK 可选；不同演唱者的翻唱各自为 SONG，可关联同一 WORK；SONG 下的 VARIANT 表示一次演绎、剪辑及歌词时间轴，MEDIA 表示一种编码文件，LOCATION 绑定具体来源和未转义的相对路径。不同清晰度只有经过确认才可以归属同一 VARIANT。名称相同不得自动合并歌曲。

ARTIST、RELEASE、TAG 均为独立对象；`credits` 是带 ARTIST UUID、实际署名和连接符的有序数组，同名 ARTIST 可分别登记。旧数据的 `artists` 字符串数组作为尚未确认实体的署名兼容字段保留；不凭这些名字制造已确认的歌手身份。已采用 `credits` 时它是署名的正式结构。平台标识始终包含提供者、实体类型和字符串 ID。

文件位置和身份分离。本地扫描在设备号、inode、大小、修改时间全部匹配且候选唯一时识别同源改名；其他移动通过显式重新绑定完成。WebDAV 目录或文件名变化不凭歌名猜测；可重新绑定根目录或单个媒体。大小、mtime、ETag 是观测线索，不是跨来源内容摘要。普通扫描不得为取得身份而完整下载网盘文件。只有已取得完整内容或用户明确发起校验时才计算媒体 SHA-256。

## 当前正式文档

数据库保存当前正式文档。管理、搜索、点歌、歌词、封面及分享均经正式资料服务读取；旧 `/media-songs` 是兼容投影。自动输入是证据，不是绕过服务的覆盖层。人工订正直接修改当前正式字段，无需再次“保存到文件”。Go 是唯一业务写入方，compute 仅提交观测结果。

文档包含 `fields` 与一一对应的 `states`。每个状态包含 `origin`、`decision`、`status`、字符串 `revision`。来源与本地决定分离：共享者人工修改的内容在接收方是 SHARED/AUTO，接收方确认后才变成其本地决定。`parentState` 可记录本地确认的父级关联，保护已手动调整的版本关系。

写接口携带 `expectedRevision`、UUID `requestId` 和字段操作。并发修订不符返回 409；重复相同请求返回已提交回执；同一请求标识配不同内容返回 409。操作为：

| 操作 | 正式值 | 后续自动任务 |
|---|---|---|
| SET | 写入所提供的有效值，相同值也记录确认 | 本机保护 |
| CLEAR | 写入 null，状态 CLEARED | 本机保护，不重新填入 |
| RESET | 去除本地决定，重新采用持久证据 | 恢复自动规则 |
| 未提供字段 | 保持当前值 | 不改变决定 |

SET 不能用 null；CLEAR/RESET 不携带值。数组是一个合并单元，整体采用或保留；不把两个署名顺序拼接。技术 `observation` 同样整体替换，不拼接不同观测的流参数。实际时长 `MEDIA.durationMs`、版本时间轴 `VARIANT.timelineDurationMs`、曲目参考时长 `SONG.referenceDurationMs` 分别保存；播放器的 duration 取 MEDIA，未知时不得以平台参考时长冒充。

确认与当前相同的值时保留其原始来源，只把本机决定变为 SET；录入不同值默认标为 MANUAL，显式采用平台、上传或其他证据时记录对应来源。来源类型本身不决定保护级别。

自动观察先填未决定的空缺和 FILENAME 推断字段。同一已跟随来源可在当前值等于其上次基线时推进；其他来源有差异时保留当前值并记录差异。本地 SET/CLEAR 始终保留。来源基线独立于任务记录保存。RESET 的默认候选顺序为已保存的平台资料、共享资料、文件标签、文件名；不可用的旧文件证据不参与。旧 v2/v3 空白字段忽略；v4 的明确 CLEARED 可随已跟随来源传播，但不会变成接收方的本地 CLEAR。

共享方删除仅产生提示；本机屏蔽存入独立可见性决定并在后续导入保持。删除来源只解除位置关系；媒体失联、解除来源与删除正式资料是不同操作。

## 保存与资源生命周期

附件资源 ID 是**原始文件字节 SHA-256**。UTF-8 歌词原文、图片等先写临时文件、同步、原子改名并校验，再登记资源与提交正式引用。替换附件下载失败时保留原正式引用；文字可以先提交。原图支持 JPEG/PNG/WebP、1 字节至 32 MiB、最多 67,108,864 像素。展示缩略图单独生成；不得以缩略图替代原图。清空缓存不影响正式附件。

资源引用覆盖 CURRENT、IMPORT、EXPORT、UPLOAD。当前资料引用无到期时间；后台任务的租约在任务保留期内有效。未被任何引用或租约使用的附件进入七天回收宽限。旧的 base64 文本摘要通过别名映射到原始字节摘要；缺失的旧附件不制造假原图，文字继续保留。

资源声明的 MIME 必须匹配实际内容；同一原始摘要不能重新登记为不同类型。歌词资源在被正式引用前还必须通过 256 KiB 与歌词语义校验。独立 ZIP 校验器使用相同的原图类型、尺寸、UTF-8 和引用校验。

保存状态（文字已保存／附件待保存／衍生文件待生成）、字段情况（PRESENT、UNREAD、MISSING、NOT_APPLICABLE、CLEARED）与媒体状态（PENDING、PRESENT、MISMATCH、MISSING、UNREACHABLE、UNBOUND）分别记录。目录发现仅表示路径存在，不代表已验证分段读取、音轨或播放兼容。连接失败不能判成删除。

文件属性变化使相关 FILE 技术证据失效，歌曲人工资料和附件继续保留。JSON、NFO、STRM 是带修订检查的后台衍生物，失败重试；导出从固定事务冻结正式文档和附件引用，不读取正在更新的衍生文件。首版保存当前值、来源、修订与合并基线；不承诺历史回滚。

迁移或兼容导入时，旧格式不符合新字段规则的值保留在原始证据中，不升级成正式值，也不阻止其余有效字段入库；缺失的日期精度、原图和强校验结果不得补造。新规范文档和新人工写入始终严格校验。

## 互操作与能力

JSON 必须 UTF-8，无 BOM、重复键、未配对 UTF-16 转义或尾随第二份文档；最大嵌套 64。重复键包括转义后相同的键。核心数值不得超出 ±9,007,199,254,740,991；身份、平台 ID、修订号用字符串。修订为 1..9223372036854775807 的十进制字符串。日期只保留已知精度（YYYY / YYYY-MM / YYYY-MM-DD），不补造月份和日期；时长为正整数毫秒，最多七天；帧率为整数有理数。整数单位字段、数量及字节大小使用十进制整数字面量，不使用小数点或指数表示；独立校验器补充检查这些 JSON Schema 无法约束的原始表示规则。

文档及清单摘要采用 RFC 8785 JSON Canonicalization Scheme：UTF-16 键排序、ECMAScript 数值序列化、无额外空白、无 Unicode 归一化。附件和分片摘要直接覆盖文件字节。JSON Schema 使用 Draft 2020-12；严格解析、日期、字段状态对应、引用关系和包摘要还必须通过独立校验器。

能力可声明 `core/1`、`music/1`、`ktv/1`。core 允许资料尚未补齐；music 要求歌曲有标题与演唱署名、版本有 kind、其他音乐对象有名称；ktv 在此基础上要求版本时间轴、媒体实际时长、观测与音轨信息。未知必需能力拒绝应用。未知可选扩展必须放在 `extensions` 中，键如 `org.example:rating`，可以保留并再导出；不得通过未知顶级字段扩展核心。

## 独立校验

从仓库根运行（不启动业务服务，不连接数据库，不需要 compute）：

```sh
sh scripts/run-go.sh run ./cmd/metadata-validate "$PWD/contracts/metadata/examples/song.valid.json"
sh scripts/run-go.sh run ./cmd/metadata-validate /path/to/share.zip
sh scripts/run-go.sh run ./cmd/metadata-validate --schema
```

有效返回 `valid` 和退出码 0，失败返回原因和非零退出码。Schema 可单独分发；CLI 另验证 JSON 严格性、类型语义和 ZIP 完整性。完整资料包可在新 NAS 重建资料并绑定自己的媒体。账号、密钥、系统任务及完整运行状态恢复仍需数据库、认证密钥、持久资料目录的备份。

参考：RFC 8259、RFC 8785、JSON Schema Draft 2020-12；v4 清单借鉴 RFC 8493 的完整性清单思想，不声称是 BagIt 包。
