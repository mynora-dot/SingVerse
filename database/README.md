# 数据库初始化与验证

当前按**首次部署、从零建库**维护 SQL。SQLite 与 MySQL 各保留一份完整的 dbmate 初始化基线：

- `migrations/sqlite/202611070001_initial_schema.sql`
- `migrations/mysql/202611070001_initial_schema.sql`

此前每种数据库的 38 份迁移已合并并删除。基线直接定义表、字段、约束、索引和必要单例，不执行旧迁移链的转换。它适用于空数据库，不提供更早开发版本的升级路径；后续在此基线上新增迁移，不修改已部署的基线。

两种方言的 `202611080001_background_tasks.sql` 创建任务概览与明细快照，`202611090001_background_task_batches.sql` 增加独立批次状态、共享任务关系及扫描处理范围，并导入已确认的旧 parent 关系。应用启动依次应用基线和增量迁移，`schema_migrations` 记录 `202611070001`、`202611080001`、`202611090001`；已经部署基线的数据库只应用新版本。最新增量 down 仅移除批次扩展，原任务概览/明细保留；更早任务增量 down 移除任务中心快照，原曲库和业务任务保留；初始化基线 down 仍会移除全部业务结构，只用于隔离验证库。

## 结构与初始值

业务表覆盖认证、媒体来源与解析、歌曲索引和扫描、元数据审核与分享、AI 与分类、歌手与图片、TV 与聚会、歌单、转码与音轨、缓存、真实播放统计及缺歌反馈。SQLite/MySQL 保留各自适用的文本、二进制、自增及索引定义；Go 不自动建表，业务 SQL 继续放在 模块内嵌 SQL。

- WebDAV 的文件大小和修改时间允许为空；扫描暂存与正式索引采用相同语义。
- 缓存策略直接默认 `HYBRID`，设置 revision 从 `0` 开始，高/低水位为 `90/75`。
- 歌曲、播放记录、缓存索引、固定偏好及播放实例初始为空；播放统计单例直接为 `ready=1, phase=READY`，无需等待历史回填。
- 管理员仍由应用认证初始化流程创建及计算密码摘要，SQL 不预置密码、密钥、真实设备或媒体数据。
- 外键、唯一键、CHECK 与业务查询索引在首次建库时创建，回退按依赖逆序删除业务表。`down` 仅用于可丢弃的验证库，不由应用启动流程自动执行。

## 从零验证

```sh
# 无需启动后端、前端或 Docker；仅使用临时 SQLite，结束自动清理。
make db-fresh-check

# 从临时 SQLite 启动真实 Go 服务并验证 HTTP、显式 SQL 和业务结构。
make db-sqlite-check

# 完整 Go 业务回归；各测试使用各自隔离数据。
make go-backend-test
```

`db-fresh-check` 使用真实 dbmate，验证首次 `up`、重复 `migrate`、逐级 `down` 和再次建库，比较完整结构及种子，并检查外键、热度/固定约束、空业务数据和默认值；还验证增量迁移及其回退保留原曲库和任务记录、真实 parent 关系被导入。它固定使用自身临时目录，不读取本地 `.env`、不使用 `SQLITE_PATH`、不操作任何已有数据库。此检查也接入 `db-sqlite-check` 和 Go CI。

`make db-mysql-check` 自动启动独占的 MySQL Docker 容器，绑定本机随机端口并使用隔离数据；执行真实 SQL、事务与 HTTP 业务回归后只清理该测试实例。它不读取已有业务 MySQL 配置，也不操作已有库。连接成功不等于业务兼容，未运行该检查时应明确标记未验证。

手工从零启动可给 `SQLITE_PATH` 指定一个全新文件路径，或使用新的 Docker Compose 项目与其独立数据卷；不要用旧库验证这份基线。现有命名卷和实际数据库由使用者保留或另行处理，本次整理不删除它们。

连接及驱动选择 见[数据库策略](../docs/database-strategy.md)，账号与主密钥见[认证说明](../docs/authentication.md)。数据库、WAL/SHM、凭据和主密钥不得提交；切换驱动 不自动迁移数据。

## 洛雪下载增量迁移

两种方言的 `202611090003_lx_downloads.sql` 新增唯一目标/音源绑定单例、加密音源版本、目录缓存、下载批次和逐曲明细，以及长期来源记录，共 6 张表。媒体来源的 `useForLxDownloads` 由单例绑定推导，不增加重复布尔存储；事务写锁保护唯一绑定。活动请求与解析音质分别有可空唯一键，结束后释放；下载来源独立于记录保留，重扫按文件大小、修改时间沿用元数据。此增量 down 只移除下载表，不删除媒体文件、原曲库或既有任务表；不可在正式库中回退后声称仍能恢复下载状态。

## 伴奏配方增量迁移

`202611090002_audio_separation_profiles.sql` 为 SQLite/MySQL 增加任务/批次 recipe_json 和 media_audio_selection；不修改已部署初始基线。默认旧行按 LEGACY_DEMUCS/AAC 解释；新配方隔离缓存，当前版本按媒体指纹绑定。`make db-fresh-check` 验证空库、重复应用及回滚重建；未连接真实 MySQL 的检查不能代替 MySQL 验收。
