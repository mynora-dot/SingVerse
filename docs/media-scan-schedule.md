# 媒体来源定时扫描

在“媒体库管理”的添加或编辑弹窗中勾选“启用定时扫描”，填写标准五段 cron：

```text
分 时 日 月 周
0 3 * * *        每天 03:00
*/30 * * * *     每半小时
0 3 * * MON-FRI  工作日 03:00
```

固定按 `Asia/Shanghai`（上海）时区执行，与宿主机器时区无关。支持星号、数字、列表、范围、步长及英文月份/星期缩写；星期 0 和 7 都表示周日。日与星期同时受限时采用 Unix 的“任一满足”规则；其中任一日字段以 `*` 开头（含 `*/步长`）时，按两项同时满足处理。不接收秒/年字段、Quartz 的 `? L W #` 或 `@daily` 等宏；表达式无效或没有可执行日期时保存返回 400，原配置保留。

功能默认关闭。本地目录、WebDAV 均可配置；旧客户端创建时省略新字段保持关闭，编辑时省略新字段保留原计划。禁用清空下次时间、保留表达式供再次启用。列表展示开关、表达式、下次时间、上次触发状态及失败提示。

## 调度行为

设置通过 模块内嵌 SQL 保存，SQLite/MySQL 的 `202611070001_initial_schema.sql` 直接定义配置、下次执行、上次触发状态及到期查询索引。服务每 10 秒检查到期来源，条件更新成功才领取任务并立即推进下次时间。实际开始可延迟约 10 秒或更久（有并发扫描时），不保证秒级准点。

本地扫描使用独立的两个工作线程，复用手动本地扫描及其同来源互斥和原件保护规则；WebDAV 复用原有后台任务队列，同来源已有任务或队列已满时本次跳过，不立即重试。下一次 cron 到期仍会再尝试。定时任务不阻塞元数据刮削的调度线程。

服务重启后读取持久化下次时间。如果已经过期，只尝试一次并从当前时间计算下一次，不按遗漏次数补跑。领取后进程崩溃不会重放该次领取；没有分布式执行或“严格仅一次成功”保证，当前部署仍为单 Go 实例。

上次触发的 `QUEUED` 表示 WebDAV 扫描已进入后台队列，最终完成、失败或取消仍看“扫描状态”；本地扫描结束记录 `SUCCEEDED` 或 `FAILED`。扫描中触发跳过记录 `SKIPPED`，不取消已有扫描。调整或关闭计划不会强制中断已经开始的扫描；扫描期间编辑来源/解析方案仍遵循原有快照冲突保护。

计划只更新歌曲索引，不修改或删除媒体原件，原有扫描数量、目录深度及时间预算不变。部署需保证服务持续运行以及目录挂载/WebDAV 凭据可用；不会唤醒已停止的容器。API 新字段参见 [OpenAPI](../contracts/openapi/singverse.openapi.json)。
