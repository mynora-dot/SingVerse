# 批量元数据刮削工作台

页面仍为 `#/library/songs/metadata`。空闲时优先配置平台并启动；有批次时优先展示控制、整体进度和分类统计，设置折叠为摘要且可重新展开。保存设置前明确提示会暂停运行批次，保存后重新读取真实状态；自动写入默认关闭、平台请求间隔及 HTTP 429 冷却不变。

## 统一统计

此前 `total/completed` 只统计需要平台查询的明细，`skippedExisting` 单独存放，导致视觉上混用整体与可处理数量。现在接口统一为：

| 字段 | 定义 |
|---|---|
| total | 本批次检查的全部歌曲，包括跳过项 |
| pending | 尚未处理；终止后仍保留该状态供追溯，不再执行 |
| processing | 已领取且请求正在进行；暂停/终止后可能短暂存在 |
| review | 查询结束、待人工审核；已经完成处理，尚未应用 |
| applied | AUTO_APPLIED 与 MANUAL_APPLIED 之和 |
| failed | 查询或保存失败，已完成本轮处理，可按规则重试 |
| skippedExisting | 创建时已有有效确认元数据且文件未变化，保留原结果 |
| completed | review + applied + failed + skippedExisting |
| processableTotal | pending + processing + review + applied + failed，即 total - skippedExisting |
| legacySkipped | 旧批次只保存汇总、没有歌曲 ID 的跳过项数量 |
| observedAt | 本次一致性事务实际读取时间；并非歌曲更新时间 |

整体 `total = pending + processing + review + applied + failed + skippedExisting`，进度为 `completed / total`。例如旧界面 9 首可处理、2 首待审核、3 首跳过，真实整体为 12 首，已处理 5 首，约 42%。待审核与待处理不会重复计数；匹配完成不表示成功写入。终止不强行把未处理项标记为成功，完成比例可以小于 100%；重试将 REVIEW/FAILED 放回 PENDING，已处理数和比例可能降低，这是实际状态变化。

列表、全局统计及批次状态通过同一读取事务返回，明细筛选不改变全局统计。新批次会将跳过歌曲保存为 `SKIPPED_EXISTING` 明细并记录原因；不会给这些歌曲发平台查询，也不改变已有元数据保护。旧批次没有保存跳过歌曲 ID，不能可靠回填，所以只计入整体汇总，页面明确说明它们没有可搜索明细。旧批次“全部明细”数量可能小于整体总数；这不是分页丢数据。

## 可信提示与操作

不改变相似度算法或分值。后端额外返回审核提示 `confidence`：

- HIGH：最高候选分达到该批次创建时的阈值，展示为“高相似度”。
- LOW：最高分至少 0.8，但未达到该批次阈值。
- NONE：没有候选，或最高分低于 0.8。5% 的候选保留显示，但标明无可信匹配、仅供核对。

0.8 来自现有自动写入阈值的最低允许值；分类是保守的展示参考，不是正确率，不会过滤或替换候选。自动写入实际仍须遵守批次快照、当前全局开关/更高阈值；并不是 HIGH 标签即可触发写入。

审核窗口自动选中达到阈值的最高分候选，同分保留服务端顺序；存在接近候选时仍在审核预览中提示核对，不影响批次自动写入。自动选中只更新审核预览，不触发应用接口，仍须确认字段后写入；未达到阈值不自动选中。

REVIEW 有候选时直接复用单曲双栏审核工作台，支持当前有效元数据对照、字段编辑与封面选择。确认时使用批次审核接口 `/api/v1/metadata/batches/{id}/items/{itemId}/review/apply`，按单曲审核的版本与幂等规则写入，并将批次明细标为 `MANUAL_APPLIED`。低可信时操作称为“核对候选”，重新匹配是次要操作。无候选或无可信匹配仍可通过 `reviewSongId` 深链接进入单曲工作台。

通过批次“审核候选”确认会更新该批次明细；从“手工处理”深链接独立确认不会回写旧批次审核历史。已应用/跳过项可查看结果或原因，并前往单曲重新处理；它们不能通过批次 retry 强行再次覆盖。失败项显示已有原因及重试，处理中不提供重复请求按钮。

重新匹配仅将明细放回等待处理。若该批次已启用自动写入，仍按原有规则执行，操作前会再次说明；全局自动写入关闭时不自动应用。终止保留已写入结果和候选、停止后续处理，不能续跑或重试终止批次，可新建批次。部分平台错误会保存在审核明细提示中，成功平台候选继续可审核。

## 查询、滚动与接口

批次接口新增 `q`（创建时歌名/歌手字面包含，最多 200 字符）、`sort=DEFAULT|TITLE|SCORE_DESC|UPDATED_DESC`，支持 `status=APPLIED` 汇总筛选和 `SKIPPED_EXISTING`。筛选和排序在数据库分页前完成；SQL 均在 模块内嵌 SQL，排序使用固定分支，搜索转义百分号/下划线，仍为每页 20、最大 100。

当前单批次上限仍为 5000，全库/选中规则不变；包含查询可能扫描批次内明细，未引入全文索引。稳定排序以明细 ID 兜底。原始歌曲列是创建时快照，候选列独立展示平台信息，当前有效确认封面和候选封面有实际引用时才请求代理，缺失使用统一音乐占位。

批量路由专用布局让顶栏保持普通布局项、主内容作为唯一纵向滚动容器，表格不另设固定高度或吸顶表头；横向空间不足时只在表格容器内滚动。侧栏及其他路由布局不变。自动读取运行批次约每 2 秒一次，错误时延长到 5 秒；审核窗口打开时暂停轮询，离页清理计时器。最近读取时间来自真实响应，读取失败保留上次数据并显示错误，不模拟进度。

此次无需迁移表结构。新状态使用现有 metadata_item 字段，旧批次只做诚实的汇总兼容；部署需要更新 Go 和完整前端产物。新增字段和口径见 [OpenAPI](../contracts/openapi/singverse.openapi.json)。
