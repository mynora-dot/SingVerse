# 歌曲元数据刮削

入口为“整理 → 歌曲信息”（`#/library/songs/metadata`）。先扫描自备媒体，使歌曲进入歌曲管理；文件名解析方案仍负责首次提取歌名、歌手及版本标签，刮削用于补全或人工修正平台元数据。

## 使用流程

1. 在顶栏“设置 → 音乐平台”（`#/system/music-platforms`）管理网易云音乐、QQ 音乐、酷狗音乐、酷我音乐和汽水音乐。新安装默认启用全部五个平台，自动应用默认关闭；升级保留已保存的选择。平台、自动应用、相似度阈值和请求间隔在同一页保存，离页与刷新保护未保存修改。歌曲信息页显示实际设置摘要，单曲审核的“管理平台”可直达设置并返回原歌曲或批次。查询仅发送搜索关键词（通常为歌名与歌手），不上传、下载或修改媒体文件，不使用平台账号 Cookie。
2. 单曲点击“元数据刮削”：可修改关键词、选择已启用的平台重新搜索；选择候选、勾选要应用的字段，再确认写入。
3. 批量可勾选当前页歌曲后点击“刮削已选”，或在刮削页启动“刮削全部歌曲”。已应用且文件未变化的歌曲跳过，需要重新匹配时使用单曲入口。
4. 页面展示进度、待审核、失败与已应用数量，支持明细筛选、分页、暂停、继续、终止和逐项重试。批次“匹配完成”仅表示查询结束，待审核项仍需选择候选并确认。

单次选中最多 500 首；全库或指定媒体来源的批次最多 5000 首，超过上限拒绝启动，应按页分批。批次页可选择全部媒体来源或单个媒体来源；不跟随歌曲列表的来源/文件名筛选。创建指定来源批次时发送 `all=true` 和 `sourceId`，不能同时提供指定歌曲 ID。当前只展示最近批次或指定 `?batch=ID` 的批次，无批次历史列表。

## 写入与原件保护

可应用歌名、歌手、专辑、发行日期、别名、平台时长及封面。仅更新勾选且候选有值的字段，缺失值不会清空已有确认内容；每个字段记录平台、外部 ID 与确认时间。平台时长是平台提供的信息，不代表已探测本地文件。

当前正式资料保存在 `metadata_document`，旧 `song_metadata` 保留为兼容写入与迁移证据。人工订正直接修改正式字段，并保存本机决定；标签、平台自动任务和共享更新不能覆盖本机 SET/CLEAR。重新扫描或文件属性变化只重新核验相关媒体证据，不使歌名、人工订正及已保存附件整体失效。来源移除解除位置绑定，资料继续保留。完整身份、字段和附件规则见[元数据存储标准 1.0](../contracts/metadata/README.md)。

`#/library/songs` 按歌曲和版本管理；`#/library/songs/files` 保留按文件审核。标准更新接口区分 SET（包括确认相同值）、CLEAR（明确清空）和 RESET（解除本机决定）；所有读取与导出使用当前正式资料。平台参考时长、版本时间轴和文件实际时长分别保存。

自动写入默认关闭，只有明确启用并保存后，新批次才会记录启用快照。默认相似度阈值为 95%，可设为 80%～100%；排序第一的候选达到有效阈值即自动应用，同分时取服务端排序第一条。相似度由歌名与歌手字符串计算，是启发式参考，不是正确率；版本词不被抹掉，缺少歌手不会达到自动阈值，接近候选不再阻止自动写入。单曲搜索始终等待确认。关闭自动写入会阻止旧批次自动写入；提高全局阈值也会约束旧批次。

## 批次与故障

Go 单体内每次处理一首，第三方请求不占用业务数据库事务；每个平台串行且两次请求启动至少间隔 1.5 秒，连接超时 3 秒、单次 HTTP 请求超时 5 秒、JSON 响应最多 2 MB。平台变化、限流、网络故障会显示失败或部分平台警告，可换平台、修改关键词或重试；不自动绕过限制。

批次、明细、候选与配置均经 模块内嵌 SQL 持久化。保存设置会暂停运行批次；服务重启将运行批次恢复为暂停，处理中项回到等待，用户确认平台设置后继续。暂停/终止不保证撤回已经发出的网络请求，但提交前会复核状态，停止后不再自动应用该请求结果。终止保留已获取候选和已应用内容，不能续跑或重试，可新建批次。人工确认仍可审核终止批次的已有候选。

候选有效期为 7 天，过期需重新搜索；启动新批次会清理过期候选。应用时校验候选归属和文件属性，变化返回 409。旧批次应用接口在同一事务中提交字段与状态；共享单曲审核工作台的批次接口先按单曲审核幂等写入，再更新明细状态，重试相同提交标识可补齐状态。当前为单 Go 实例执行器，不支持多实例争抢同一任务。

## 封面与部署

封面走受管理员会话保护的同源代理，只接受对应平台固定 CDN 的 HTTPS URL，拒绝重定向和私有地址。平台图片默认读取原图，不再受旧的 2 MB / 4096×4096 限制，不改变像素或重新编码；可选原图或高清，加载成功显示实际像素。单次网络与缓存读取最多 32 MiB、超时 20 秒，超出时明确报读取失败，可选择高清；只接受实际 JPEG/PNG。无效或不可达封面不影响已确认文本。本地上传、持久保存与 v4 分享统一支持 32 MiB 原图，最多 67,108,864 像素；展示缩略图单独生成，不重新编码正式原图。浏览器不直接加载平台封面 URL，不提供任意 URL 代理或音频地址接口。

缓存默认 `./data/metadata/covers`，可设置 `METADATA_CACHE_PATH`。它是衍生缓存，放在可写数据卷，和只读媒体目录分开；Compose 显式使用 `/data/metadata/covers` 并复用现有 Go 数据卷。缓存目前没有自动容量清理；停用平台后已缓存封面仍可显示，新下载需要功能及对应平台启用。正式原图和歌词进入 `WEBDAV_METADATA_PATH/assets/<摘要前两位>/<SHA256>.bin`；缓存清空后仍可读取正式附件。资源通过正式引用和任务租约保护，未引用资源有七天回收宽限。完整恢复须备份数据库、主密钥与持久资料目录。

SQLite/MySQL 的 `202611070001_initial_schema.sql` 直接定义原有元数据设置、任务、候选和兼容记录；`202611110001_metadata_standard.sql` 成对新增正式文档、位置、证据、合并基线、资源引用与回执，启动时分批回填旧资料。所有 `/api/v1/metadata/**` 接口受管理员会话保护，写入/搜索操作需要 CSRF；契约见 [OpenAPI](../contracts/openapi/singverse.openapi.json)。

平台适配、协议签名及解析测试参考相邻 ktv-home 项目的 MIT 实现，许可证保留于 [third-party/ktv-home-LICENSE.txt](third-party/ktv-home-LICENSE.txt)。未移植其下载、播放、外部账号 Cookie 或独立服务结构。

批量刮削可在平台设置中配置每首完成后的等待范围（默认 3～8 秒，允许 0～300 秒，含端点；最大值不得小于最小值）。设置持久化且保存时暂停活动批次，续跑使用当前间隔；等待不占用数据库连接。同一平台请求仍保持串行及至少 1.5 秒启动间隔；HTTP 429 会触发该平台至少 60 秒冷却，期间拒绝新请求，失败项可稍后手动重试。单曲搜索也受平台冷却约束，批量间隔只约束后台批次。设置为 0 秒表示不额外等待，但任务调度约每秒检查一次，同平台仍受请求启动间隔约束。随机间隔用于平滑流量，不能保证避免限流或自动化识别。

单曲元数据使用双栏审核工作台，批次候选审核复用同一组件，支持字段编辑、受管 JPEG/PNG 上传、平台封面搜索及统一确认应用。新增接口、资源备份、幂等与版本校验规则见[单曲审核](single-song-review.md)。

批量工作台已统一整体进度：total/completed 均包含跳过项，新批次持久化跳过明细，旧批次仅汇总并提示。新增批次内搜索/排序、可信度审核提示及按状态操作，自动写入改为第一候选达到有效阈值即执行；限流规则不变。接口兼容说明及统计定义见[批量工作台](batch-metadata-workbench.md)。

## 图片平台与原图（2026-11-10）

歌曲搜索、额外封面搜索、设置及批次共用上述五个平台。新安装默认全部开启，升级仅更新未修改的初始配置；已有保存的配置和自动应用开关保留。调整时在“设置 → 音乐平台”选择并保存。酷狗读取歌曲搜索的专辑 Image；酷我读取公开歌曲目录及 web_albumpic_short，汽水读取公开歌曲与专辑 url_cover，均不获取平台音频或平台账号 Cookie，不用歌手头像代替专辑封面。酷我对未修改的“有效歌名 歌手”查询按完整歌名请求，再沿用原有歌名/歌手评分排序，避免其组合关键词模糊查询遗漏原唱；自定义查询不改写。

原图使用平台原始地址：网易云不带尺寸参数，酷狗与酷我用 0 尺寸版本，汽水用 image.image，QQ 不带 R 尺寸段。高清使用平台实际提供的版本（网易云/酷狗/酷我/汽水为 2048，QQ 为 1500）；实际像素以返回图片为准，不人工放大。确认时服务端按候选与画质推导并保存 URL，浏览器缩小展示不改变文件。旧客户端不传画质时默认原图。
