# 单曲元数据匹配与审核工作台

歌曲卡片“编辑”或列表内编辑入口打开“核对歌曲信息”工作台 `SingleSongScrapeDialog.vue`；批次审核复用同一工作台，任务和批量接口不变。单曲始终人工确认，不因分数高而自动写入。

## 使用

顶部优先显示有效歌名、歌手与媒体格式；文件位置及当前有效信息按需展开。手机在“查找匹配候选 / 核对与编辑字段”之间切换，未启用平台时直接进入字段区。平台时长是已确认的平台信息，不表示探测了本地文件；没有内嵌标签探测或本机绝对路径展示。文件变化使旧确认结果失效时，使用原文件名解析值并明确提示。

搜索可选择已启用平台、修改关键词并回车。左侧候选独立滚动，右侧预览并对比当前值、候选/编辑值；勾选真正有值且发生变化的字段，确认按钮显示可应用变更数。平台总体相似度保持原算法，不伪造分项匹配理由或请求阶段进度。部分平台失败与全部失败/无结果分别显示。

“编辑元数据”支持歌名、歌手、专辑、发行日期、别名及平台时长。歌手、别名以顿号分隔，最多 20 项，每项 200 字符；歌名/专辑最长 500 字符；发行日期接受 YYYY、YYYY-MM、YYYY-MM-DD 并验证真实日期；时长界面输入秒（最多三位小数），API 使用整数毫秒，范围 1～86400000。原平台值与编辑值分开显示，编辑过的字段明确标记。没有平台候选或平台未启用时仍可手工编辑、上传封面。

保存编辑仅更新本次草稿。未选择、空值和无变化字段不覆盖已有值，不提供以空值删除现有元数据的能力。覆盖已有值显示“将修改”，主窗口需手工勾选并确认。关闭有草稿修改的窗口、切换有手工编辑的候选会要求放弃确认。编辑子窗口未保存修改时也会提示。

## 封面

“选择封面”展示当前封面、当前歌曲候选自带图片，并支持以歌名/歌手/专辑再次查询所选平台。额外搜索复用已有网易云/QQ/酷狗搜索适配器及限流保护，返回真实专辑封面，不引入新数据源或 API 密钥。平台未返回尺寸时显示未知；上传资源返回实测尺寸。封面查询失败不清空歌曲匹配结果。缩略图网格可选择，所选图片可查看大图。

本地上传接受实际内容为 JPEG/PNG 的文件，最大 2,000,000 字节、4096×4096 像素。服务器同时校验 MIME、头部尺寸并完整解码后重编码，生成 UUID 文件名、去除原图片元数据；不使用客户端文件名或外部 URL 作为保存路径。上传进度来自实际 XHR，传输完成后仍等待服务器校验成功。上传与应用分开显示：上传成功进入受管存储，选择后进入草稿，主窗口确认后才成为歌曲封面。

受管文件位于现有 `METADATA_CACHE_PATH` 下的 `uploads/`，Compose 仍使用 `/data/metadata/covers/uploads/`。现有同源图片接口继续代理平台封面；受管图片由受管理员会话保护的资源接口提供，不公开磁盘路径。平台图片沿用固定 CDN HTTPS、禁止重定向、私有地址检查、大小/图片格式限制。

更换封面只修改当前歌曲的确认引用，不删除原媒体或其他歌曲图片；不提供删除当前封面的接口。未应用或已被替换且不再引用的上传资源，超过七天后由每小时清理任务处理（每轮最多 100 条资源）；进程崩溃遗留的孤立文件也按七天期限扫描清理。受管图片必须和数据库一起备份，不能把 `uploads/` 当成可随意清空的代理缓存。清理不是即时执行，不提供无限容量保证。

## 写入与并发

仍使用独立 `song_metadata` 覆盖层，不修改 `media_song.result_json` 或原始媒体文件。沿用逐字段 origins，扩展 `kind=PLATFORM|MANUAL|UPLOAD`；旧 origin 没有 kind 时仍可读取。手工来源可以没有平台 ID，平台候选的手改字段保留其平台关联并标记 MANUAL，未修改的字段保持来源。

单曲工作台打开时读取文件 fingerprint 和确认数据 version。应用事务锁定现有元数据协调行后，验证两者未变化；平台候选及额外封面还须属于当前歌曲、文件一致且未过期。编辑值优先于所选候选值，未应用字段保留现有有效值，不能用客户端图片 URL 绕过受管封面选择。

每次确认生成 requestId；相同 ID 与相同请求可在七天内返回已提交回执，避免连接超时重试造成重复写入；同 ID 不同内容拒绝。元数据写入与回执同事务提交，失败全部回滚。冲突时保留前端草稿，用户可重新加载最新数据（需确认放弃草稿）。成功反馈来自服务端的 updated、skipped、retained 和前后值，三类字段集合互不重叠。

## 接口与迁移

均位于 `/api/v1/metadata`，复用管理员会话、同源及 CSRF；POST 必须带 CSRF。

| 接口 | 用途 |
|---|---|
| GET `/songs/{songId}/review` | 当前歌曲、有效值、文件指纹与版本 |
| POST `/songs/{songId}/review/apply` | 候选/编辑/受管封面的统一确认应用 |
| POST `/songs/{songId}/covers/search` | 额外封面候选，复用现有平台 |
| POST `/songs/{songId}/covers/upload` | multipart 文件与 fingerprint，返回资源 ID |
| GET `/cover-assets/{id}` | 鉴权读取上传图片 |

旧 search、apply、封面代理以及批量接口保持兼容。契约见 [OpenAPI](../contracts/openapi/singverse.openapi.json)。SQLite/MySQL 的 `202611070001_initial_schema.sql` 直接定义上传资源、幂等回执及确认元数据表，业务 SQL 使用 模块内嵌 SQL。无需新增外部服务或密钥。从空库部署由 dbmate 初始化，并保留可写封面数据卷。

Nginx 仅对 `/api/v1/metadata/songs/{id}/covers/upload` 放宽 multipart 请求体到 3 MB，其他业务接口仍保留原 16 KB 上限；后端实际文件上限为 2,000,000 字节。反向代理自定义部署也应只对上传路径设置合适上限。

## 单曲工作台布局与状态（第二轮修复）

弹窗使用纵向 flex，标题/操作栏为不滚动的布局项；桌面两栏各有滚动容器，右栏包含完整预览、字段表与末尾提示。窄屏或低高度窗口使用主体滚动，不采用覆盖式固定操作栏。顶部入库摘要与平台提示缩紧，摘要长文本保留并可滚动。

平台总开关、可用平台和用户选择分别判断；总开关关闭时平台不勾选且不可操作，并提供现有刮削设置入口。尚未搜索、搜索中、无结果、请求失败和部分平台失败分别显示，未搜索不报结果数。手工编辑与封面入口始终可用。

重新搜索与取消候选恢复当前入库值、清理旧候选/封面/字段选择；存在手工草稿时先确认。右侧应用预览只合并已勾选的有效变更，字段表保留候选/编辑值供对比，取消应用显示“不应用”。成功窗口收紧，统计和前后值仍来自服务端，只有真实 updated 包含封面且 after 有值时尝试加载已确认图片，失败降级为文本。

搜索完成后，达到已保存相似度阈值的最高分候选会自动选中并更新字段审核预览。同分取服务端排序第一项，接近候选仍提示人工核对；未达到阈值保留未选择状态。单曲自动选择不自动写入，仍须确认应用；批量自动写入开启时，排序第一的候选达到有效阈值即可写入。


歌曲列表对文件名解析“待复核”的歌曲显示主按钮“去复核”，详情中也提供入口，均复用现有单曲元数据审核工作台，可手工编辑或搜索候选，勾选字段后确认应用。完整匹配歌曲保留“元数据刮削”入口。元数据确认仍保存到独立覆盖层，文件名解析状态及待复核筛选语义不变；工作台明确说明这一区别，不修改原媒体。
