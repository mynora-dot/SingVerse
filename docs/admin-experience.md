# 家庭音乐资料室：网页管理端

网页为手机、TV 和亲友点歌准备内容。网页中的试听与播放用于核对媒体、音轨、伴奏和兼容性。产品不把浏览器变成新的 K 歌客户端；助手沿用现有形象与展示能力，不提供尚未实现的对话或工具调用。

## 入口与功能对应

主导航为概览、曲库、添加与整理、电视与反馈。设置与任务在顶栏右侧；手机的全部导航列出所有入口。二级导航只展示当前工作区。页面路径保持兼容，名称与组织可以改变。

## 视觉与组件

以纸面、唱片与家庭收藏为视觉线索：暖白背景、深绿文字与操作、陶土细节。歌曲使用真实封面；缺图使用明确标注的唱片纹理占位，不代替实际封面。歌手使用真实图片与单字占位，歌单沿用真实封面来源。排版、内容比例与导航结构共同建立媒体软件体验。

管理主题按令牌、Element Plus、原生控件、共用业务布局、应用外壳、登录拆分。`PageHeader`、`TaskGuide`、`SongCover` 与既有危险确认组件复用。复杂配置保持信息密度；技术参数放在对应配置或展开区。桌面保留表格内部横向滚动，平板与手机调整列数、表单和审核布局。所有主操作使用按钮 / 链接，焦点可见，导航面板限制键盘范围并恢复焦点，尊重减少动态效果偏好。

| 状态 | 呈现与下一步 |
|---|---|
| 尚未准备 | 空曲库、缺节点、无 AI 分别说明原因并提供对应入口；不阻止不依赖该能力的功能 |
| 处理中 | 显示真实阶段 / 已知数量；后台任务可离页，前端轮询按原业务规则停止 |
| 需要确认 | 候选、草稿、当前值、过期结果有区别；明确确认字段或建议后再应用 |
| 完成 | 使用服务端结果确认更新项、保留项与成果版本，完成不等于全部已审核 |
| 失败 / 部分失败 | 保留输入、上次可用结果与重试标识；局部错误不让整页空白 |
| 冲突 / 未保存 | 原有版本检查与草稿确认保留；歌单增加导航和浏览器关闭提醒 |

## 接口与验证边界

仅扩展 `GET /api/v1/media-songs?search=`；旧 `q` 的文件路径含义不变。新搜索在 Go 使用与展示一致的有效信息投影，和原有 SQL 筛选处于同一事务，先过滤计数再返回页。排序沿用 `scannedAt DESC, id ASC`，特殊字符按字面匹配。流式仅保留当前页，不向浏览器传全库；大曲库仍有线性投影成本，后续如需索引需另行设计迁移与失效更新，不在本次引入。OpenAPI 与 SQLite / MySQL 业务测试同步覆盖。

首页复用既有分页接口，不新增汇总服务。移动 / TV / compute 源码不变，不新增云端依赖。浏览器、合成媒体及本机数据库检查不代替 NAS、微信和 TV 真机。

### 同日本机 Docker 更新

按用户要求将运行中的前端替换为 `singverse-frontend:admin-redesign-20261110-arm64`，并同步新搜索必需的 `singverse-go-backend:admin-redesign-20261110-arm64`。前端由标准 Dockerfile 完整构建；Go 基础镜像仓库连接重置后，使用仓库固定 Go 1.27.3 交叉编译 Linux ARM64，嵌入本次前端镜像的完整资源，并复用原业务镜像运行环境及未变更的迁移。原镜像保留供回退。

切换前确认无在途批次，停机备份业务数据、密钥、计算认证和下载四个配套卷，核对备份摘要。沿用原 macOS 计算节点配置、命名卷及 `0.0.0.0:18080` 访问绑定。新镜像通过原生 ARM64 隔离容器验收（166 项契约、104 项交付断言）；运行部署的三个入口 HTML 和 95 个清单资源摘要与新镜像一致，真实曲库查询、新搜索校验和旧 `q` 查询通过，两个业务容器均健康。

`SINGVERSE_MACOS_COMPUTE=1 make docker-check` 已执行：原生节点能力 / 鉴权预检通过，但独立旧 `singverse-compute:local` 镜像的媒体标签烟测返回 HTTP 422，完整检查未通过。该失败发生在独立、无网络的 compute 测试容器中；本次未更新 compute，不把前端与 Go 的验收冒充完整计算链路验收。
