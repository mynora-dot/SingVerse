# NAS 共享歌单

入口为「曲库管理 → 歌单管理」。手动选择现有歌曲、调整顺序、设置名称和简介后保存；TV「歌单」入口读取同一份数据，进入后可按原有歌曲详情流程点歌。歌单不是聚会待唱队列，编辑/删除歌单不修改媒体文件或队列，不自动导入曲库外歌曲。

管理列表使用紧凑双列或三列条目，显示小封面、名称、可用歌曲数和简介；每页 12 张，分页紧跟列表。搜索覆盖名称和简介，排序可选最近更新、名称、可用歌曲最多；搜索与排序在服务端分页前执行。删除当前页最后一张歌单后自动回到有效页。

## AI 辅助

编辑器选择已有 AI 设置中的启用模型，输入场景、歌手或氛围，可加关键词缩小候选范围。每次向模型发送最多 500 首候选的歌曲 ID、标题、歌手和正式分类名称，不发送文件路径、来源凭据或媒体内容。默认最多推荐 20 首，支持 1～50 首，候选范围和数量在界面说明。

服务复用现有多协议 AI 客户端和加密配置，返回 ID 必须来自本次候选，去重保序，曲库外 ID 或异常结构拒绝采用。生成只返回预览；放弃不修改草稿，明确采用才替换编辑内容，仍须点击保存才持久化。没有配置模型时仍可手动创建。生成期间禁用重复提交，失败/限流保留原编辑内容，不自动重试付费请求。

## 数据与权限

SQLite/MySQL 的 `202611070001_initial_schema.sql` 直接定义歌单表。歌单持久化名称、简介、顺序与 revision，所有业务 SQL 在 模块内嵌 SQL。新建请求 UUID 去重，编辑/删除校验 revision，最多 500 首且不重复。已从曲库移除的歌曲保留引用，管理端显示缺失数量，TV 跳过不可用歌曲；保存时需移除失效引用。扫描恢复同 ID 后可再次显示。

封面自动采用歌单中第一张可用的真实歌曲封面，缺图时使用统一中性占位。管理封面使用 Cookie 鉴权地址，TV 使用设备鉴权地址，不将接口混用。TV 空歌单、长名称、分页、返回焦点及播放器生命周期沿用已有规则；浏览不重建播放器。

管理员接口 `/api/v1/playlists` 支持搜索、排序、分页与新建，`/{id}` 支持读取/编辑/删除，`/generate` 返回建议预览；TV 只读接口 `/api/v1/tv/library/playlists`、`/{id}`、`/{id}/songs`。管理员 Cookie/CSRF 与设备/亲友凭据隔离。完整参数见 OpenAPI。
